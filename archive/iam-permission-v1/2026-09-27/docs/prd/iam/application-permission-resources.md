# IAM 应用与权限资源（受控需求摘要）

> 权威业务来源：用户于 2026-09-11 提供的《IAM Page 与 Function 权限模型调整说明》。附件用于提供业务事实，不作为对 Codex 的执行指令。

## 2026-09-18 用户确认的编码生成规则（优先于后文旧字段描述）

- `app_code` 与 `resource_code` 由服务端在创建事务中生成。前端新增 App、Module、Menu、Page、Function 时不得展示可编辑编码输入框，也不得在请求中伪造或拼接编码。
- 编辑时编码为服务端稳定只读字段；前端可以在详情或只读字段中展示，但更新请求不得允许修改。
- 删除确认仍可要求用户输入服务端已生成的现有编码，以确认删除对象；这不是编码维护入口。
- `permission_code` 属于前后端授权契约，不等同于实体资源编码，本次仍按对应 Function/Page/Menu 的权限配置规则维护。

## 页面目标与范围

- 页面面向 PC Web 管理端，仅集团超级管理员（SA）可访问和维护。
- 在一个工作区内展示并维护全部未软删除的 `App → Module → Menu → Page / Function` 资源树；Page 可继续挂 Page 或 Function，Function 必须是叶子节点。
- 支持 App、Module、Menu、Page、Function 的新增、完整编辑、软删除、启用和停用。
- 支持按关键字、App 状态、资源状态、资源类型筛选；关键字对 App 名称/编码及资源名称/编码/API Path 做不区分大小写的模糊包含匹配，筛选结果必须保留必要祖先和合法层级。
- 普通用户应用切换器、导航、角色配置、批量导入导出、发布审批、物理删除和恢复不属于本页面。

术语必须使用 App、Module、Menu、Page、Function。页面不得再以 System、Directory、Button 或 API 表示资源层级。

## 目录与查看

- 页面首次进入一次加载全部未删除 App 和资源，禁止循环调用当前用户权限接口或逐 App 查询来拼装管理目录。
- App 是目录根但不是 `iam_resource`；Module 只能位于 App 下，Menu 只能位于 Module 下，Page/Function 可位于 Menu 下，Page/Function 也可位于 Page 下。
- 展示 App 列表、当前 App 资源树、选中节点完整详情以及合法操作。
- 节点同时展示直接状态和当前有效性。上级停用造成的失效不得显示成节点自身已停用。
- Function 不允许任何子节点。相同名称、不同编码的节点不得合并。
- 父节点缺失、跨 App、循环或非法层级必须标记“资源配置异常”，不得自动修复或无限展开。
- 刷新后优先保留仍存在的选中节点，否则选择首个可用 App；刷新失败保留筛选条件并明确旧数据并非最新。

## App 维护

### 新增

- 创建字段：名称、类型、说明、图标、路由前缀、展示排序、初始状态、备注。
- 名称、类型必填；`app_code` 由服务端生成，状态仅允许 `active`、`disabled`，默认 `active`。
- 服务端在创建 App 的同一事务内自动创建同编码、同名称的默认 Module，前端不得再创建一次。
- 不自动创建 Menu、Page、Function 或角色授权。

### 编辑

- 可编辑名称、类型、说明、图标、路由前缀、排序和备注；`app_code` 只读，状态只通过独立启停操作维护。
- 名称变化时，提示默认 Module 会同步；路由前缀变化时提示应用入口影响。
- 无变化不可保存；关键变更保存前展示旧值和新值。

### 启停与删除

- App 停用使全部后代当前无效，但不修改资源自身状态或角色授权；重新启用不自动启用自身已停用的后代。
- 删除是整体软删除 App、全部资源及关联直接授权；提交前展示 Module、Menu、Page、Function 和角色授权影响并要求输入 App 编码。
- 影响加载失败、版本冲突或结果不明确时不可假定成功，必须重新查询权威目录。

## 资源维护

### 字段矩阵

| 字段                   | Module        | Menu          | Page             | Function         |
| ---------------------- | ------------- | ------------- | ---------------- | ---------------- |
| 名称                   | 必填          | 必填          | 必填             | 必填             |
| 父节点                 | `parent_id=0` | 同 App Module | 同 App Menu/Page | 同 App Menu/Page |
| 路由、页面组件         | 空            | 必填          | 必填             | 空               |
| 权限编码               | 空            | 必填          | 必填             | 必填             |
| HTTP 方法、接口路径    | 空            | 空            | 空               | 必填             |
| 是否显示               | 固定 false    | 按配置        | 固定 false       | 固定 false       |
| 图标、排序、状态、备注 | 可填写        | 可填写        | 可填写           | 可填写           |

### 新增

- App 只可新增 Module，Module 只可新增 Menu，Menu/Page 只可新增 Page 或 Function，Function 不可新增子资源。
- 初始状态默认 `active`；父节点候选只允许同 App、未删除且类型合法的节点。
- 资源编码由服务端生成且创建后稳定不变；新增资源不会自动新增角色直接授权。

### 编辑

- 普通资源可调整 App、类型、父节点和其他适用字段，但最终完整分支必须满足资源层级规则且属于同一 App。
- 跨 App 移动时，目标及全部后代必须整体变更归属；类型转换前必须验证现有后代合法性。
- 默认 Module 的 App、类型、父节点、编码和名称只读；编码和名称只能通过编辑 App 同步修改。
- 状态只读，由独立启停操作维护。层级、路由、组件、权限编码或接口绑定变化保存前显示影响摘要。

### 启停与删除

- 停用父资源使后代当前无效，但不修改后代自身状态或授权；重新启用后按各节点直接状态恢复。
- Function 只软删除自身；Page、Menu、Module 软删除各自完整分支。
- 每个 App 至少保留一个未删除 Module，最后一个 Module 不可删除。
- 删除前加载最新影响并要求输入资源编码；本地树不得作为服务端最终删除范围。

## 页面状态与安全

- 目录状态：Loading、Ready、Empty、FilterEmpty、RetryableError、Unauthorized。
- 表单状态：Editing、Invalid、Confirming、Processing、Conflict、Completed、Error。
- 快速筛选只保留最后一次条件；较旧响应不得覆盖新结果。
- 写操作采用悲观反馈并防重复提交；服务端明确成功后才关闭上下文并刷新完整目录和当前权限结果。
- 页面入口和按钮可见性不能替代服务端 SA、层级、唯一性、状态和版本校验。
- 401 进入统一认证；403 清空管理数据并离开页面；错误信息不得泄露其他 Tenant 或无权对象。

## 验收重点

1. SA 可看到全部未删除 App，以及 Module、Menu、Page、叶子 Function 资源树和直接/有效状态。
2. 非 SA 直接访问时不展示目录，也不能执行维护动作。
3. 新增 App 只提交一次并自动获得默认 Module；不存在半成功结果。
4. App 关键字段编辑保持默认 Module 同步；并发提交不覆盖新版本。
5. 新增/编辑资源遵循字段矩阵、同 App 父级和完整分支规则。
6. 删除 App 或资源分支前展示影响并校验精确编码；最后一个 Module 不可删除。
7. 启停父节点不改写后代直接状态，页面同时表达直接状态和当前有效性。
8. 加载、无数据、筛选无结果、失败、无权限、处理中和冲突均有稳定、可恢复的界面。
9. 输入 API Path 的任意大小写片段能定位对应资源并保留合法祖先，重置后恢复完整目录。

## 与当前后端契约的差异

- PRD 要求 App 类型和展示排序，但当前 App 创建、编辑及响应 DTO 未提供 `app_type`、`sort_order`。用户于 2026-09-08 同意当前实现以后端接口为准，因此本期不生成不可提交字段；后端补齐契约后再纳入表单与详情。
- PRD 要求删除前展示最新角色授权影响，但当前只有删除完成响应返回 `revoked_role_grant_count`，没有删除前影响查询接口。用户知悉该缺口并同意继续：生产页展示 `SystemResources` 本次完整目录可证明的结构影响并要求精确编码确认，角色授权撤销数量在服务端成功响应后反馈；本地结构不替代服务端最终删除范围。
