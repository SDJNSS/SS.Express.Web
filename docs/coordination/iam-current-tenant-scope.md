# IAM 当前租户业务边界

本文件记录当前前端实施边界，2026-10-16 按用户提供的
`iam-current-tenant-authorization-frontend-sync.md` 更新。新规则取代 2026-10-15
关于“SA 全局入口”的授权表述：共享数据不等于全局授权。

## 当前租户业务边界

- 当前租户是登录时选择或最近一次成功切换进入的租户。可进入多个租户不等于可同时查询多个租户。
- 员工与成员、组织、岗位、角色、权限方案、培训等租户业务只按当前租户查询和维护；SA 也遵守此规则。
- 接口仍要求 `tenant_id` 或 `tenant_ids` 时，只传当前租户 ID 或单元素数组；未选定有效租户时不发租户业务请求。
- 详情、下拉候选和导出遵守同一范围。切换成功后旧数据、旧表单、旧请求及旧权限不得在新租户继续使用。
- 员工页不提供跨租户归属编辑，不能将当前租户的局部成员关系提交给全量替换接口。共享用户身份编辑须使用独立权限并提示跨租户影响。

## 当前租户授权与目录例外

- 登录、App、菜单、页面、按钮和后端 Function 均按当前 Tenant 的角色 → 权限包 → Permission → Resource 授权；不合并其他 Tenant 的 SA 资源，不增加全局授权通道。
- 集团信息、Tenant 管理、系统资源目录同样校验当前租户上下文和 CurrentPageResources。SA 身份、旧登录权限缓存、`global` 标记均不能补权。
- Tenant/Query 经对应 Function 授权后查询整个租户目录；不要求仅返回本人所属租户。Tenant/Create、Update、ChangeStatus 仍由后端验证 SA + Function。
- Tenant 目录的目标 `id` 可以不同于当前 Tenant；不向请求添加当前租户 ID 来覆盖目标条目，也不把这个例外扩展到员工、组织、岗位、角色等业务。
- 集团接口继续维护共享集团记录，按当前 Tenant 授权并保留接口原有 SA 限制。
- 本人切换候选只取登录/切换响应的 `available_tenants`，不从 Tenant/Query 推导；切换必须调用 Auth/SwitchTenant。
- 兼容查询接口由后端将缺省、单值 0 或空数组归一为当前 Tenant。前端正常查询仍显式使用当前 Tenant；不会将旧表单的其他租户参数重写成新租户。

前端隔离不是后端授权替代。Tenant 不一致时保留服务端“先切换租户”提示；权限不足进入 403；会话/成员失效走统一认证失效流程；版本冲突保留填写内容并提示刷新后重试。页面视觉变更仍由 UIDesign 审核，不在本次自动批准或重录基线。
