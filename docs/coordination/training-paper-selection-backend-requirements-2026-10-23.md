# 题库与试卷选题改造 后端配合要求

日期：2026-10-23。接收方：培训后端开发会话。

## 2026-10-24 进展及决策覆盖

本地后端已提供 `TrainingPaper/GeneratePreview` 及固定/随机统一最终 `questions` 契约，权威 Function 为 `IAM.TRAINING_PAPER.GENERATE_PREVIEW`。已核对 DTO、控制器、服务与权威目录，前端按最终版本接入，详见 `docs/api/training-content-exam-api.md`。实际部署、真实考试执行及资源授权仍须各负责方核验。

用户明确：**不再兼容旧数据，旧数据将全部清除。** 因此下文第七节及验收项中有关旧随机规则卷、同型不等分旧固定卷的兼容、升级和迁移要求不再适用，不作为本次开发阻碍。清理由用户/后端负责；前端不删除任何数据，也不保留旧模型写入回退。历史说明保留仅供追溯，不应据此恢复旧流程。

本文用于前后端协同实施。业务决策已由用户确认；下文新增字段、端点名称属于建议契约，需后端实现并提供最终文档后，前端再据实接入。当前仅输出需求文档，没有修改业务代码、数据库、系统资源或授权。

## 一 已确认的业务范围

1. 题库列表展示已有题目 `id`，只读，不新增人工编号。
2. 新建、编辑多选题允许只有一个正确答案，即至少一个正确答案；不是只能有一个。其他题型规则及多选题至少三个选项的规则保持不变。
3. 组卷改造属于 `/iam/training/papers` 的新建、编辑试卷；`/iam/training/exams` 仍关联试卷，不在考试配置中复制组卷流程。
4. 固定组卷使用选题抽屉，按单选、多选、判断分 Tab，支持关键词搜索、服务端分页、跨页保留勾选；确认后按题型分组展示，可以移除、替换。
5. 随机组卷按题型数量、分数生成一次初稿，人工可以移除和替换，包括跨题型替换。**最终确认保存的题目就是正式考试使用的题目，之后不再随机抽取题目。**
6. 允许两位小数分数。“整除”按两位小数精度下精确均分理解，不要求每题为整数分，不允许四舍五入或给个别题补尾差。
7. 题目顺序随机、选项顺序随机仍是独立设置。它们可以改变顺序，但不能改变最终题目集合。

## 三 题库接口调整

### 多选题

- `POST /iam-admin/TrainingQuestion/Create`、`Update` 均允许一个或多个正确选项，零个正确选项仍拒绝。
- 单选题仍恰好一个正确选项；判断题仍保留原有选项及正确答案规则。
- 同步校验错误文案、接口文档及测试，不能只改前端提示。
- 若有答题、评分或导入链路依赖“多选题必有至少两个正确答案”，一并核对。按实际正确答案集合处理，不因仅一个正确答案而自动改成单选题；不在本次顺带修改多选题计分政策。

### 候选查询

继续复用 `POST /iam-admin/TrainingQuestion/Query`：`keyword`、`question_type`、`status=ACTIVE`、`page_index`、`page_size`。

- 新选择、替换候选均限当前 Tenant 内未删除且启用的题目；不能根据客户端传入的 Tenant 扩大范围。
- 返回 id、完整题干、题型、状态、updated_at，以及准确 total、分页字段。选题列表不需要正确答案或解析，不额外扩大敏感内容返回范围。
- 各 Tab 的 total 必须使用同一候选口径，不用某一页长度冒充可选题量。
- 已选项通过前端选择状态和试卷 Detail 回显即可；不要求为了这个交互另造选题接口。若确需按 ID 批量补齐，提供有界批量查询，不让前端遍历全库或逐题请求详情。

## 四 随机生成预览接口

建议端点：`POST /iam-admin/TrainingPaper/GeneratePreview`。这是待新增的建议名称，不是当前已存在接口；后端可以给出等价正式契约。

### 入参能力

- 能在试卷尚未创建、没有 paper_id 时生成预览。
- 接收按题型配置的数量及分值；建议明确采用题型总分或每题分数的一种主输入，若两者都传必须校验一致。
- 数量为非负整数，至少一种题型大于零；数量不得超过当前租户实际可用题量。
- 分值遵循第五节规则。零题型没有有效分值，不能提交零题数除法或占用试卷分数。
- Tenant、操作人来自会话，不由前端填写。

### 返回能力

- 返回真实抽中的具体题目：question_id、完整题干、实际题型、状态、updated_at，以及明确的排序。
- 返回各题型实际数量、题型总分、每题分数及全卷合计，便于前端校验与分组。
- 从完整的当前 Tenant 合格候选范围服务端抽取，不只从前端已加载的一页抽取；同次结果不重复，题量不足明确失败，不静默少抽或跨题型补齐。
- 不返回选题界面不需要的答案、解析。

### 行为与鉴权

- 只生成本次编辑初稿，不创建试卷、考试、学习记录，不发布、不自动保存、不修改既有试卷版本。
- 用户确认后提交最终题集。保存接口不得重新抽题，即使输入的题目与最初预览不同，也按最终显式题集校验保存。
- 允许用户以后主动重新生成，但不能因打开详情/编辑、切 Tab、搜索、打开替换框或保存而隐式重抽。未保存的人工调整由前端确认后才可丢弃。
- 作为业务只读能力登记 Function，使用普通业务鉴权及当前 Tenant 范围，不做 SA 豁免、匿名或仅登录放行。需可供“新建试卷”“编辑试卷”Permission 组合。
- 无须仅为预览引入异步任务、轮询或持久化考试记录；如后端引入预览凭据，需说明有效期、重试及失效行为，不能阻碍按最终题集保存。

## 五 分数与题型分组规则

### 精确均分

对本次新建或显式升级到新计分规则的试卷，同一题型内采用相同的每题分数，最多两位小数；题型总分必须能在该精度下精确均分。旧版固定试卷的非等分配置按第七节兼容，不自动改分。

例如：1 分分给 4 题，每题 0.25 分，合法；10 分分给 3 题，无法精确到两位小数均分，拒绝；9.99 分分给 3 题，每题 3.33 分，合法。

服务端使用 decimal 或整数百分之一分做精确校验：题数 n > 0 时，将不超过两位小数的题型总分转换为整数百分之一分 S，要求 `S % n == 0`。先算出整数的每题百分之一分 `S / n`，再以 decimal 除以 100 转回每题分数，且必须大于零；最后一步不能使用整数除法。不能使用浮点近似或先四舍五入再宣告可分。

### 增删与替换

- 新增、移除导致某题型题数变化：前端将该组分数清零/标为待重设，不允许直接保存。
- 跨题型替换：同步减少原题型数量、增加新题型数量，重新归组，原、新两组分数均待重设；不影响其他题型的分数。
- 同题型替换且题数不变：建议保留该组分数；如果后端业务有额外要求，请在最终契约中说明。
- 某题型变成零题：清空该组分数，不保留“有分无题”；当前随机规则契约为 count=0 时 score=null，新增契约须明确对应空值。
- 试卷目标总分不因换题静默改变。最终题目分数之和、各题型小计之和均须等于目标总分，未分配分数或不相等时拒绝保存。
- 服务端重新按题目的真实题型计算分组、数量、分数，不能信任前端传入的题型或合计。

## 六 Create Update Detail 与正式考试执行

### 最终题集契约

新模式的 Create、Update 必须接收最终完整题集，并原子保存题目引用、逐题分数与排序。可复用固定题关系表，但字段命名不能让前端误以为随机生成的题目不能提交。

最终题集至少表达 question_id、question_score、sort_order；建议附带选题时的题型及 question_updated_at 作为预期值，后端发现题目已被修改、题型变化或不可用时明确报冲突，不能静默用另一道题代替。若采用其他版本机制，应提供等价契约。

组卷来源“人工选择/随机生成”与正式执行“使用已确认题集”应明确区分：随机生成表示来源，不表示每次考试重新抽题。后端需明确 paper_mode、生成来源、最终题集确认状态如何表达；不要求沿用本文建议字段名，但不能悄悄将来源信息丢弃。

### 保存与回读

- Create、Update 不补抽、不重抽，最终题集为唯一准据；不能只保存各题型数量。
- 校验题目存在、归属当前 Tenant、无重复、分数与顺序合法。新加/替换题目必须启用；既有固定试卷原题停用时可保留的编辑规则继续兼容，不因此将所有停用历史原题剔除。
- 采用现有 updated_at 乐观并发控制，前端完整回传，不截断精度。整体更新失败时不部分保存题目或分数。
- Detail 对人工选择和随机生成的新试卷均返回完整最终题集，包括题型、题干、状态、逐题分数、排序及回显所需版本；不能在 RANDOM 分支返回空题集或重新抽样。
- Query、Detail、考试配置中引用的试卷摘要，要能区分新已确认题集与旧仅有规则的试卷，避免前端猜测。
- 只有最终题集有效、分数校验通过的试卷才能启用及被新考试采用。

### 正式考试和历史记录

- 核对考试实例、补考/重考、培训任务引用试卷等实际执行入口：对新已确认试卷，必须使用保存的最终题集，不再按随机规则选题。
- 可以按既有设置打乱题目或选项顺序，但题目 ID 集合和对应分数不能改变。
- “锁定题目集合”不等于擅自改变题干、选项、答案的快照时点。请明确沿用的考试实例/历史快照机制；后续编辑题库或试卷不得覆盖既有考试记录和评分依据。
- 若实际考试执行链尚未实现，应明确列出缺口，不能仅完成管理接口就宣称正式考试已使用最终题集。

## 七 旧数据兼容与回退

当前 RANDOM 数据只有规则。无法从旧记录恢复一份原本未保存的最终题集，因此不能把旧数据直接当成新已确认试卷。

- 不删除或重建既有试卷 ID、考试配置、任务引用及考试历史。
- 旧固定试卷允许逐题设分，可能存在同题型分数不相同的记录。保留其原始逐题分数和可识别的旧计分规则，不能按平均值回显后静默覆盖；转入新分组等分规则时需显式确认、重新配分。请明确旧记录只改名称等基本资料时的兼容读写方式，不能因部署新均分校验就让未改分的历史记录失效。
- 后端明确区分旧规则记录与新已确认题集。旧规则通过显式的生成、确认、保存流程升级，不能在读取或部署时后台自动抽一次并锁定。
- 新执行策略不得导致旧规则被误当作空试卷。说明过渡期旧记录可否继续使用、如何标识；用户已确认的新流程不再重抽，旧兼容不能被当成新流程默认行为。
- 已经建立的历史考试继续遵循原快照，不追溯重算。升级应保留必要来源和版本，提供可核验的迁移与回退方案。
- 回退旧后端/旧客户端时，不能让它们按新的“随机生成”来源再次抽题；不兼容的读写或考试生成应显式拒绝，而不是丢弃最终题集、覆盖为旧规则。

## 八 后端交付与验收清单

请交付最终 Method/Path、请求/响应 Schema、错误契约、Function 编码及鉴权分类、版本并发规则、旧数据兼容策略和实际部署版本。新增 Function 同步到后端权威清单/运行时 Manifest；本文不预先编造已存在的资源编码。

至少覆盖：

1. 多选题一个/多个正确答案成功，零个失败，单选/判断规则不变。
2. 题型、关键词、分页组合正确，候选及预览不越 Tenant，数量口径一致。
3. 预览覆盖完整候选、去重、题量不足失败，不产生试卷/考试写入。
4. 多题型选择、删除、跨题型替换后，保存和 Detail 回读得到相同的最终题集、数量、分数和顺序。
5. 精确均分三个示例、零题型、未分配分数、总分不符均按第五节校验。
6. 选题后题目被停用、删除、修改或跨 Tenant 引用时给出明确错误，不自动替换；保留历史原题的例外按正式契约测试。
7. updated_at 冲突整体拒绝，不部分写入，前端可保留草稿后刷新处理。
8. 正式考试及重考对新试卷均不重抽；顺序随机不改变题集。旧规则、历史快照、迁移和回退路径有单独测试证据。
9. 旧固定试卷同题型不等分时，查看、基本资料维护不改写分数；显式升级后再校验新均分规则，既有考试快照不受影响。

参数非法、题量不足、题目失效、并发冲突、权限不足应有可区分的稳定错误标识和可理解文案；最终格式沿用项目错误信封，不在前端靠匹配中文猜原因。预览失败保留编辑输入，保存失败不自动重试已可能完成的写操作。

2. 前端改造完成后，再单独输出“实际按钮与资源调整清单”，交资源维护者验收、同步。本节只是交接计划，不是可执行的入库清单，不现在更新数据库或角色授权。
