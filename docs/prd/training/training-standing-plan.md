## 1. 目标与业务模型

现有年度培训之外，增加两类长期运营场景：

- **入职培训**：使用常设计划和长期任务，自动接收规则启用后新生效的当前 Tenant 员工；不补录启用基线前已有员工。
- **返岗培训**：管理员为当前 Tenant 员工显式安排，每次安排形成独立执行轮次，旧轮次与历史结果永久保留。

长期任务没有员工完成期限，不进入逾期口径；员工完成率达到 100% 也不代表任务关闭。管理员可以完成某一员工的某一执行轮次，但该动作不得生成学习记录、考试答题、分数或通过结果。

## 2. 培训计划

- 计划类型固定为 `ANNUAL`（年度）与 `STANDING`（常设）。
- 常设计划不要求且不得提交年度、结束时间和频率，页面统一展示“长期有效”。
- 年度计划保留既有年度、有效期和 `MONTHLY` / `QUARTERLY` 规则。
- 年度筛选未显式指定计划类型时，不得默认排除常设计划；两类计划可并存展示。
- 常设计划允许零员工配置与发布；原年度计划继续遵守既有员工范围规则。

## 3. 计划详情与入职自动纳入

- 常设计划允许创建 `TEMPORARY + is_long_running=true` 的长期任务；长期任务不要求截止时间。
- 入职自动纳入设置展示目标常设计划、目标长期任务、启用状态、生效基线及最近作业结果。
- 保存、启用或切换目标时明确提示：“仅纳入启用后新生效员工，不补录已有员工”。
- “停止接收新人”通过停用自动纳入规则实现；既有执行轮次、学习记录和考试记录不受影响。
- 自动纳入由后端后台作业完成。前端不得在账号创建或成员加入成功后串行调用培训分配接口。
- 自动纳入失败作业可按独立权限重试；失败信息、重试中状态和最终结果均来自服务端。

## 4. 长期任务与执行轮次

- 长期任务无 `deadline_at` / `period_end_at`，页面显示“无完成期限”，不得显示逾期日期或逾期标签。
- “是否继续接收新人”与“员工执行完成情况”是两种独立状态；完成率 100% 时任务仍可保持 `ACTIVE`。
- 已开放长期任务允许更新内容；新分配轮次使用新的 `content_version`，既有轮次继续读取自己的课程与考试快照。
- 返岗培训只能选择当前 Tenant 有效员工；每次提交使用新的 `request_id` 创建新 `execution_no`，相同请求安全重试时返回原轮次。
- Tenant 切换必须使旧员工候选、任务候选、分页结果和在途请求全部失效。

## 5. 任务员工与管理员完成

任务员工列表至少展示：

- 员工、参加时间 `assigned_at`、执行轮次 `execution_no`；
- 分配来源 `assignment_type`（`PLAN` / `ONBOARDING` / `RETURN_TO_WORK` / `MANUAL`）；
- 培训状态、课程进度、考试状态；
- 完成来源 `completion_source`（`NORMAL` / `ADMIN`）；
- 管理员完成的操作人、时间和原因。

管理员完成规则：

- 只对指定 `training_task_employee_id` 对应的本次执行生效。
- 操作入口同时受 `iam:training:task-employees:admin-complete` Function 与响应字段 `can_admin_complete` 控制。
- 确认内容必须包含员工、任务、执行轮次及风险说明，并要求填写原因。
- 成功后刷新员工列表、任务统计和相关详情；已完成记录不可重复操作。
- 失败保留原因和当前上下文，复用同一 `request_id` 安全重试；本期不提供批量管理员完成。
- 风险文案明确说明：此操作不生成课程学习、考试答题、分数或通过结果，也不自动办理复岗。

## 6. 档案、统计与导出

- 同一员工的多次返岗执行按独立轮次保留，展示分配来源、内容版本、完成来源及管理员审计信息。
- 报表支持按执行轮次、分配来源、完成来源和参加时间范围筛选。
- `employee_task_count` 表示执行次数，`distinct_employee_count` 表示去重员工数；页面必须明确区分两种口径。
- 管理员完成计入培训完成数与培训完成率；课程完成、考试提交、分数及通过率仍只使用真实课程与考试事实，不被同步改写为 100%。
- 无截止时间记录显示“无完成期限”，不参与当前逾期或曾逾期展示。
- 导出遵循页面当前服务端筛选范围，并保留执行轮次及管理员完成审计字段。

## 7. 恢复历史成员与边界

- 关联已有账号首次加入 Tenant 可被后端识别为新员工。
- 恢复历史成员关系不自动重做入职培训；需要复训时由管理员显式安排返岗培训。
- 前端不通过修改历史结果实现内容升级、重复安排或管理员完成，所有写入均使用服务端提供的版本、执行记录标识与幂等键。
- 员工客户端、批量管理员完成、伪造学习/考试结果和自动办理复岗不在本次范围。

## 8. 验收重点

1. 年度与常设计划并存，默认年度筛选不隐藏常设计划。
2. 常设计划和长期任务在零员工时可配置、发布或开放，并正确展示长期有效与无完成期限。
3. 入职规则只接收启用基线后的新成员；停用不删除既有执行，失败作业可按权限重试。
4. 同一员工多次返岗产生可追溯的独立轮次，历史课程与考试内容不被新版覆盖。
5. 管理员完成只改变本次培训完成状态，课程、考试和通过率仍反映真实数据；失败可安全重试。
6. 档案、统计和导出明确区分执行次数与去重员工数，并支持新筛选字段。
7. Tenant 切换后不出现旧 Tenant 的候选、任务、结果或迟到响应。
8. 受影响 Page Contract 和 Candidate Preview 经三视口与交互验证后重新人工审批；旧审批和旧基线不得自动沿用。
