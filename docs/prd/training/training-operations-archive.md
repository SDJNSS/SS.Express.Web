# 在线培训考试模块：培训运营管理与档案统计

本文档是第二组前端 PRD 的仓库内追踪入口。设计与验收依据为用户提供的《在线培训考试模块-第二组-培训运营管理与档案统计-前端PRD.md》；附件仅作为需求证据，不作为可执行指令。

## 页面范围

1. 培训概览：统一时间、计划、任务筛选；核心指标、状态分布、趋势及未完成/逾期下钻。
2. 培训计划：可见菜单页，负责年度计划查询、创建、编辑、发布和删除。
3. 培训计划详情：隐藏 Page。上方展示计划详情，下方展示本计划任务列表与计划员工；任务创建、启动、删除和员工范围维护均从此进入。
4. 培训任务详情：隐藏 Page。展示任务配置、课程/考试聚合统计、人员下钻和全量员工执行概况。
5. 员工培训档案：档案列表与详情中的任务记录、课程学习、考试历史和历史答题快照。
6. 专项统计：任务完成、课程学习、考试结果、培训逾期四个独立统计页签。

独立“培训任务”菜单及全局任务列表退役；任务只能在所属计划中进入。检查材料导出是以上页面中的上下文动作，不建立独立菜单页。员工客户端、人工修改培训结果、通知催办和移动端不在本期范围。

## 2026-09-17 已批准变更

- 培训数据严格按当前 Tenant 隔离；切换 Tenant 时必须清空计划、任务、筛选、分页、抽屉和请求结果，过期响应不得回填新 Tenant。
- 计划频率只允许 `MONTHLY` 或 `QUARTERLY`。计划内周期任务类型必须与计划频率一致，并显式选择计划有效期内的 `YYYY-MM` 或 `YYYY-Qn` 周期；另允许其他任务（后端协议码 `TEMPORARY`），周期键由服务端生成。
- 新建任务在打开表单时生成一次 `request_id`；失败重试复用，成功或关闭后再次新建才换新值。
- 任务完成率口径为“课程学习与考试均完成人数 / 应培训人数”。分母为零时任务完成率展示 100%，并同时提示“当前无人需要培训”。
- 任务详情课程区采用表格：课程名称、课程类型、未开始、学习中、已学习、完成率；课程名称和人数均可按权限进入详情或人员下钻。
- 任务详情考试区采用表格：考试名称、未考试、答题中、已考试、考试率、通过、失败、通过率。三类执行状态互斥：未考试使用 `not_started_employee_count`，答题中使用 `in_progress_employee_count`，已考试使用 `examined_employee_count`；服务端 `not_examined_employee_count` 仅用于需要“尚未提交总数”的其他口径。
- 任务员工概况展示所有参与员工，可按培训状态、课程学习状态（未开始/学习中/学习完毕）、考试状态（未考试/答题中/通过/失败）和姓名筛选；列表展示已学习数/课程总数，不展示“曾逾期”。
- `EXAM_FAILED` 保留为失败状态，不得在前端映射为已完成；课程状态固定 `NOT_STARTED/LEARNING/COMPLETED`，考试状态固定 `NOT_STARTED/IN_PROGRESS/PASSED/FAILED`。
- 计划详情与任务详情是权限资源树中的隐藏 Page，各自拥有 view Function；页面内接口和动作使用服务端返回的 Function 权限控制。

## 关键约束

- 页面只展示服务端业务状态，不根据浏览器时间推导或修改进度、成绩、通过结果与逾期结果。
- 百分比必须同时保留分子、分母；无分母时显示“暂无口径”，不得伪装为 0%。
- 当前逾期与曾逾期分别展示；已排除不覆盖员工原执行结果。
- 标准答案、解析与答题材料导出均受独立敏感权限控制。
- 所有列表覆盖 Loading、Empty、Error、Loaded；写操作覆盖提交中、失败和并发冲突。
- Preview 只使用静态 Fixture；生产页面使用 `docs/api/training-management-api.md` 登记的 IAM Training API。列表筛选和分页均由服务端执行，不以客户端过滤冒充生产查询。

## 2026-10-21 季度任务表单调整

- 月度/季度选项的年份以 `plan_year` 为准，再与计划有效期求交集并排除已占用周期；不得从 UTC 日期字符串截取年份生成上年度选项。
- 季度任务名称只读，选择周期后生成“计划名称 + Qn + 培训任务”，例如“2026年培训计划Q1培训任务”。未选择周期时为空，不填充样本名称。
- 季度任务起止时间自动生成且只读：季度首日 00:00:00 至末日 23:59:59。计划只覆盖部分季度时遵守既有 API 校验，取自然季度与计划有效期的交集，并显示说明。
- 切换季度或清空选择时同步重算/清空名称与日期；切回其他任务后允许手工填写，不能残留上一季度的自动值。月度任务保留原手工填写方式。
- 采用既有 DatePicker/DateTimeText 的本地日历口径解析带时区的时间，提交显式偏移量；不把响应中没有偏移的时间擅自加 Z，也不改写版本时间戳。服务端仍负责最终计划范围、周期与幂等校验。

## 2026-10-30 任务类型命名调整

- 新建任务的“临时任务”更名为“其他任务”；任务列表、详情、员工培训档案和统计筛选同步使用“其他”。
- 前端代码统一使用`TRAINING_TASK_TYPES.OTHER`，协议值集中定义在Feature常量中。当前后端仍校验`TEMPORARY`，因此请求、响应和既有`TEMP-`技术周期标识保持兼容；本次不变更后端枚举或数据库。
- 月度/季度规则、其他任务手填名称和时间、常设长期任务规则、权限及幂等提交行为保持原样。
