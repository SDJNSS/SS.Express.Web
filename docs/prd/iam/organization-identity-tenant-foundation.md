# 《IAM 组织、身份与租户基础 前端 PRD》

> **2026-09-18 编码生成裁定（优先于本文历史字段清单）**：集团、Tenant、组织、岗位及 Tenant 成员的实体编码均由服务端在创建时生成，前端不得展示可编辑编码输入框、采集编码或在创建/更新请求中回传编码；编辑态仅允许只读展示服务端返回值。Tenant 成员的系统生成显示名称同样不由更新接口提交。`permission_code` 属于权限授权契约，不是实体编码，仍按权限资源规则维护。

# 1. 前端范围

## 1.1 本期包含

本 PRD 针对 **PC Web 管理端及其登录入口**，包含：

- 集团公开信息展示与集团信息维护。
- Tenant 查询、创建、更新、启用和停用。
- Tenant 内组织树查询、创建、更新、层级调整、启用和停用。
- Tenant 内岗位查询、创建、更新、启用和停用。
- 全局用户与 Tenant 成员查询及维护。
- 成员组织归属、岗位归属及历史记录维护。
- 登录、登录后选择 Tenant、已登录状态切换 Tenant、退出。
- 各页面的权限控制、状态反馈、并发冲突、重复提交和异常刷新处理。

## 1.2 本期不包含

- 微信小程序、H5、App 等其他终端。
- 系统目录、菜单资源、角色、功能权限、数据权限及其配置页面。
- 组织授权、岗位授权、角色模板和角色继承。
- 密码修改、密码重置、首次登录修改初始密码页面。
- 登录会话列表、会话过期管理、强制退出其他登录等 Session 管理功能。
- 登录日志、IAM 操作审计和审计导出。
- 多因素认证、单点登录、LDAP、SCIM、短信或扫码登录。
- 用户邀请、批量导入、批量导出和审批流程。
- Tenant 层级树、多集团切换和新增集团。
- 集团、Tenant、组织、岗位、用户、成员及归属关系的物理删除。
- `isolation_mode`、`db_key`、`schema_name` 等部署或数据库隔离信息的前端展示和维护。

# 2. 用户角色

| 角色 | 可访问模块 | 核心操作 |
|---|---|---|
| 未登录访问者 | 登录页 | 查看集团公开展示信息；使用登录名和密码登录 |
| 普通用户 | 登录与 Tenant 上下文 | 登录、选择或切换本人可进入的 Tenant、设置默认 Tenant、退出 |
| Tenant 管理员 | 集团公开信息、当前 Tenant 信息、组织管理、岗位管理、当前 Tenant 成员、登录与 Tenant 上下文 | 查看当前 Tenant；管理当前 Tenant 的组织、岗位和成员；创建新用户并加入当前 Tenant；按完整登录名查找现有用户并加入当前 Tenant |
| 集团超级管理员 | 全部模块 | 维护集团信息；管理全部 Tenant；管理任意 Tenant 的组织、岗位、全局用户和成员；创建 Tenant 并设置初始管理员 |

权限说明：

- 页面、按钮和数据范围均以服务端返回的当前用户权限为准。
- Tenant 管理员不得看到跨 Tenant 管理入口或全局用户维护入口。
- 普通用户不得进入任何主数据管理页面。
- 集团超级管理员管理 Tenant 内数据前，必须明确选定目标 Tenant。

# 4. 模块需求

## M01 集团信息

### 模块职责

在登录页展示当前部署唯一集团的公开品牌信息，并向集团超级管理员提供完整集团信息的查看和维护入口。

### 功能清单

| ID | 功能 | 优先级 |
|---|---|---|
| M01-F01 | 查看集团信息 | P0 |
| M01-F02 | 更新集团信息 | P0 |

## M01-F01 查看集团信息

### 1. 功能需求

- 登录页展示集团名称、集团简称、Logo 和平台展示名称。
- 集团超级管理员进入集团信息页后查看完整集团资料。
- Tenant 管理员和普通用户只能看到公开展示信息，不显示集团管理详情入口。

### 2. 进入条件

- 登录页公开信息无登录要求。
- 集团管理详情仅集团超级管理员可进入。

### 3. 页面内容

```text
登录页公开区域
├── 集团 Logo
├── 集团名称或简称
└── 平台展示名称

集团信息页
├── 基本信息
├── 品牌信息
├── 联系信息
├── 地区与语言信息
└── 更新入口
```

集团信息页展示：集团编码、集团名称、全称、简称、Logo、平台展示名称、简介、联系人、联系电话、联系邮箱、网站、地址、时区、默认语言、备注和最后更新时间。

### 4. 展示规则

- 未登录：只展示公开品牌信息。
- 集团超级管理员：展示完整信息和“编辑”操作。
- 集团未初始化或数据异常：登录页显示集团信息加载失败状态，不伪造默认集团。
- Logo 为空：展示不依赖业务数据的通用占位，不生成虚构 Logo 地址。
- 平台展示名称当前只读，不提供编辑入口。

### 5. 用户操作

#### OP-01 重新加载集团信息

##### 显示条件

- 集团信息加载失败。

##### 可操作条件

- 当前无正在进行的重新加载请求。

##### 操作过程

1. 用户点击“重新加载”。
2. 页面进入加载状态。
3. 请求最新集团信息。
4. 成功后替换错误状态；失败则保留错误状态并更新原因。

##### 成功结果

- 展示最新集团信息。

##### 失败结果

- 不展示旧信息为当前有效信息。
- 提供再次重试入口。

### 6. 业务规则

- `BR-M01-F01-01`：公开信息仅包含集团名称、简称、Logo 和平台展示名称。
- `BR-M01-F01-02`：完整集团信息仅集团超级管理员可查询。
- `BR-M01-F01-03`：一个部署只对应一个集团。
- `UIR-M01-F01-01`：非集团超级管理员不得显示集团管理详情和编辑入口。

### 7. 状态与交互规则

- Loading：显示集团信息加载状态，不短暂展示其他集团或旧缓存信息。
- Ready：按角色展示公开信息或完整信息。
- Error：显示加载失败和重新加载入口。
- Unauthorized：阻止进入集团管理页，可继续显示公开信息。

### 8. 状态与操作矩阵

| 页面状态 | 页面显示 | 主操作 | 是否可操作 |
|---|---|---|---|
| 加载中 | 加载状态 | 无 | 否 |
| 正常 | 按权限展示集团信息 | 编辑或无 | 仅集团超级管理员可编辑 |
| 初始化异常 | 错误状态 | 重新加载 | 是 |
| 无管理权限 | 公开信息 | 无 | 否 |

### 9. 约束

- 不提供集团列表和集团切换。
- 不允许通过页面参数指定集团。
- 不展示与页面任务无关的内部字段。

### 10. 并发与重复操作要求

- 重复查询不得改变页面业务状态。
- 加载过程中重复点击重新加载只发起一个有效请求。

### 11. 权限与安全要求

- 未登录访问者不得获得联系人、联系方式、详细地址或备注。
- 无管理权限时直接访问集团管理地址必须被阻止。

### 12. 异常处理

| 场景 | 页面行为 |
|---|---|
| 集团未初始化 | 显示“集团信息尚未初始化”，提供重试 |
| 存在多个有效集团 | 显示系统配置异常，不任意展示其中一个 |
| 完整信息访问被拒绝 | 返回安全页面并提示无权限 |
| 网络异常 | 显示加载失败，不将占位信息当作真实集团信息 |

### 13. 验收标准

#### AC-M01-F01-01 公开信息

Given：用户未登录且集团已初始化。

When：打开登录页。

Then：展示集团名称、简称、Logo 和平台展示名称，不展示管理信息。

#### AC-M01-F01-02 管理信息

Given：当前用户为集团超级管理员。

When：进入集团信息页。

Then：展示完整信息和编辑入口。

#### AC-M01-F01-03 异常信息

Given：集团未初始化或集团数据不唯一。

When：页面加载集团信息。

Then：显示错误状态，不展示任意集团作为替代。

## M01-F02 更新集团信息

### 1. 功能需求

- 集团超级管理员编辑集团名称、全称、简称、Logo、简介、联系人、联系电话、联系邮箱、网站、地址、时区、默认语言和备注。
- 集团编码和平台展示名称只读。
- 保存成功后，当前页面及后续登录页使用更新后的公开信息。

### 2. 进入条件

- 当前用户为集团超级管理员。
- 当前部署存在唯一集团。

### 3. 页面内容

```text
集团编辑表单
├── 只读信息：集团编码、平台展示名称
├── 基本信息：集团名称、全称、简称、简介
├── 品牌信息：Logo
├── 联系信息：联系人、电话、邮箱、网站、地址
├── 地区设置：时区、默认语言
├── 备注
└── 保存、取消
```

### 4. 展示规则

- 首次进入以最新集团信息填充表单。
- 集团名称标记为必填。
- 只读字段不可进入编辑状态。
- 未修改时保存操作不可用。
- Logo 仅接受已上传且可公开展示的有效文件引用。

### 5. 用户操作

#### OP-01 保存集团信息

##### 显示条件

- 当前用户拥有集团信息更新权限。

##### 可操作条件

- 表单存在修改且校验通过。

##### 操作过程

1. 用户修改信息并点击“保存”。
2. 页面校验必填项和格式。
3. 保存期间禁用表单提交。
4. 成功后展示服务端返回的最新信息并退出编辑状态。
5. 失败后保留用户输入，显示失败原因。

##### 成功结果

- 页面展示最新集团信息。
- 登录页下次加载时展示新的公开信息。

##### 失败结果

- 原服务端数据不变。
- 并发冲突时提示数据已更新并要求重新加载。

#### OP-02 取消编辑

##### 显示条件

- 当前处于编辑状态。

##### 可操作条件

- 无保存请求正在处理。

##### 操作过程

1. 用户点击“取消”。
2. 有未保存修改时要求确认放弃。
3. 确认后恢复最近一次成功加载的数据。

##### 成功结果

- 不提交任何更新。

##### 失败结果

- 无。

### 6. 业务规则

- 引用 `BR-M01-F02-01` 至 `BR-M01-F02-05`。
- `UIR-M01-F02-01`：集团编码和平台展示名称必须只读。
- `UIR-M01-F02-02`：格式错误时不得提交。

### 7. 状态与交互规则

- Loading：加载最新信息前不开放编辑。
- Editing：允许修改可编辑字段。
- Processing：保存按钮显示处理中，禁止重复提交和退出编辑。
- Completed：使用返回结果替换页面数据。
- Conflict：保留本地输入，提示重新加载最新数据后再编辑。

### 8. 状态与操作矩阵

| 状态 | 页面显示 | 主操作 | 是否可操作 |
|---|---|---|---|
| 查看中 | 最新集团信息 | 编辑 | 是 |
| 编辑中且无修改 | 表单 | 保存 | 否 |
| 编辑中且校验通过 | 表单 | 保存 | 是 |
| 保存中 | 处理中 | 保存 | 否 |
| 版本冲突 | 冲突提示 | 重新加载 | 是 |

### 9. 约束

- 更新必须作为一个完整结果成功或失败。
- 不得通过更新新增集团、修改集团编码或切换集团。
- 未提交字段保持原值。

### 10. 并发与重复操作要求

- 保存处理中不得重复提交。
- 过期版本更新失败后，不自动覆盖服务端新数据。
- 重新加载前不得以本地旧数据再次静默提交。

### 11. 权限与安全要求

- 非集团超级管理员不得显示或调用保存操作。
- 页面参数不得改变更新目标。

### 12. 异常处理

| 场景 | 页面行为 |
|---|---|
| 必填或格式错误 | 定位字段并阻止提交 |
| Logo 无效 | 提示重新选择有效文件，保留其他输入 |
| 集团编码被修改 | 阻止提交或显示不可修改错误 |
| 并发冲突 | 提示数据已变化，提供重新加载 |
| 权限失效 | 退出编辑并阻止继续保存 |

### 13. 验收标准

#### AC-M01-F02-01 正常保存

Given：集团超级管理员已加载最新集团信息。

When：修改合法字段并保存。

Then：保存成功，集团编码不变，页面展示服务端最新结果。

#### AC-M01-F02-02 权限限制

Given：当前用户不是集团超级管理员。

When：尝试进入编辑页或提交更新。

Then：操作被阻止，集团信息不变。

#### AC-M01-F02-03 并发冲突

Given：当前表单基于旧版本集团信息。

When：用户提交保存。

Then：页面不覆盖新版本，提示重新加载。

## M02 Tenant 管理

### 2026-09-16 用户确认的交互修订（优先于本节旧字段清单）

- 列表、详情、编辑、新建及创建确认区不再展示独立的“企业名称”；创建和更新请求仍保留 `company_name`，统一取去除首尾空白后的 `tenant_name`。
- `domain`、`subdomain` 的用户可见名称统一为“域名”“子域名”。
- 每次打开新建流程时清空所有业务资料和管理员资料，不注入样本名称、编码、联系人、电话、账号或日期。仅保留时区 `Asia/Shanghai`、语言 `zh-CN`、排序 `0` 等配置默认值。
- 分步校验必填项；确认页由当前表单实时生成，区分关联已有用户与创建新用户。允许返回上一步修改；提交失败保留填写内容供修改、重试。
- 详情和创建确认区允许长文本换行，抽屉内容可滚动且提交按钮保持可访问。

### 模块职责

管理当前集团下全部平级 Tenant。集团超级管理员可完成全部维护；Tenant 管理员仅查看当前 Tenant 信息。

### 功能清单

| ID | 功能 | 优先级 |
|---|---|---|
| M02-F01 | 查询 Tenant | P0 |
| M02-F02 | 创建 Tenant | P0 |
| M02-F03 | 更新 Tenant 信息 | P0 |
| M02-F04 | 启用或停用 Tenant | P0 |

## M02-F01 查询 Tenant

### 1. 功能需求

- 集团超级管理员查看集团内 Tenant 分页列表和详情。
- Tenant 管理员查看当前 Tenant 基本信息，不显示其他 Tenant。
- 普通用户仅在选择或切换 Tenant 场景查看本人可进入 Tenant 的简要信息，该行为在 M06 定义。

### 2. 进入条件

- 集团超级管理员或 Tenant 管理员已登录。

### 3. 页面内容

```text
Tenant 管理页
├── 关键词筛选
├── 状态筛选
├── Tenant 列表
│   ├── 编码、名称、类型
│   ├── 企业名称、时区
│   ├── 状态、排序
│   └── 行操作
├── 分页
└── Tenant 详情
```

详情展示：Tenant 编码、名称、类型、状态、企业名称、联系人、联系电话、联系邮箱、地址、Logo、时区、默认语言、排序、备注、创建时间和最后更新时间。

### 4. 展示规则

- Tenant 一律按平级列表展示，不显示父级、下级或树形结构。
- 集团超级管理员看到全部 Tenant 和“创建 Tenant”入口。
- Tenant 管理员仅看到当前 Tenant 详情，不显示列表筛选、创建、编辑和状态操作。
- `ACTIVE`、`DISABLED` 必须显示明确状态标签。
- 不展示数据库隔离、数据库键、Schema 等内部字段。

### 5. 用户操作

#### OP-01 筛选 Tenant

##### 显示条件

- 当前用户为集团超级管理员。

##### 可操作条件

- 页面已完成首次加载。

##### 操作过程

1. 输入关键词或选择状态。
2. 执行查询并回到第一页。
3. 使用返回结果刷新列表和总数。

##### 成功结果

- 仅显示符合条件的平级 Tenant。

##### 失败结果

- 保留筛选条件，显示加载失败和重试入口。

#### OP-02 查看 Tenant 详情

##### 显示条件

- 列表存在目标 Tenant，或当前用户为该 Tenant 管理员。

##### 可操作条件

- 用户对目标 Tenant 有查看权限。

##### 操作过程

1. 用户打开详情。
2. 页面加载目标 Tenant 最新信息。
3. 成功后展示详情；失败时显示原因。

##### 成功结果

- 展示目标 Tenant 详情。

##### 失败结果

- 不显示其他 Tenant 的替代数据。

### 6. 业务规则

- 引用 `BR-M02-F01-01` 至 `BR-M02-F01-03`。
- `UIR-M02-F01-01`：任何角色都不得看到 Tenant 树。
- `UIR-M02-F01-02`：Tenant 管理员的管理页面固定为当前 Tenant。

### 7. 状态与交互规则

- Loading：列表或详情显示独立加载状态。
- Empty：显示“暂无 Tenant”，不显示空表格占位行。
- Ready：显示分页结果和角色允许的操作。
- Error：保留查询条件并允许重试。
- Unauthorized：阻止显示目标 Tenant 信息。

### 8. 状态与操作矩阵

| 用户角色 | 页面显示 | 主操作 | 是否可操作 |
|---|---|---|---|
| 集团超级管理员 | 全部 Tenant 列表 | 创建 Tenant | 是 |
| Tenant 管理员 | 当前 Tenant 详情 | 无 | 否 |
| 普通用户 | 不显示管理页 | 无 | 否 |
| 无查询结果 | 空状态 | 清除筛选 | 是 |

### 9. 约束

- 列表中同一 Tenant 只能出现一次。
- 分页、关键词和状态筛选以服务端结果为准。
- 查询不到目标时不得显示同名或同编码的其他 Tenant。

### 10. 并发与重复操作要求

- 快速重复查询时只呈现最后一次有效查询结果。
- 页面刷新后重新读取服务端当前状态。

### 11. 权限与安全要求

- Tenant 管理员不得通过修改地址或参数查看其他 Tenant。
- 普通用户不得进入 Tenant 管理页。

### 12. 异常处理

| 场景 | 页面行为 |
|---|---|
| Tenant 不存在 | 显示不存在并关闭无效详情 |
| 权限不足 | 阻止访问，不展示数据 |
| 查询结果为空 | 显示明确空状态 |
| 网络异常 | 保留筛选条件并允许重试 |

### 13. 验收标准

#### AC-M02-F01-01 集团列表

Given：集团内存在多个 Tenant，当前用户为集团超级管理员。

When：进入 Tenant 管理页。

Then：以平级分页列表展示全部 Tenant，不显示层级关系。

#### AC-M02-F01-02 Tenant 管理员限制

Given：当前用户为 Tenant A 管理员。

When：进入 Tenant 管理页或尝试访问 Tenant B。

Then：只展示 Tenant A；Tenant B 访问被阻止。

#### AC-M02-F01-03 状态展示

Given：列表同时存在启用和停用 Tenant。

When：列表加载完成。

Then：两种状态均明确显示，停用 Tenant 不被误认为已删除。

## M02-F02 创建 Tenant

### 1. 功能需求

- 集团超级管理员在一次操作中创建 Tenant，并建立至少一名立即有效的初始 Tenant 管理员。
- 初始管理员支持“选择现有用户”和“创建新用户”两种方式。
- 创建结果必须整体成功或整体失败。

### 2. 进入条件

- 当前用户为集团超级管理员。
- 当前集团已初始化。

### 3. 页面内容

```text
创建 Tenant 表单
├── Tenant 基本信息
│   ├── 名称、类型、企业名称（Tenant 编码由服务端生成）
│   ├── 联系人、电话、邮箱、地址
│   ├── Logo、时区、默认语言、排序、备注
│   └── 状态说明：创建后默认启用
├── 初始管理员
│   ├── 使用现有用户 / 创建新用户
│   ├── 用户确认或新用户资料
│   └── 成员编号、显示名称（服务端生成）、有效期、备注
└── 创建、取消
```

- 新用户资料：登录名、姓名、昵称、手机号、邮箱、头像、用户类型。
- 页面不提供初始密码输入；固定初始密码规则只通过必要提示说明。
- 新 Tenant 尚无组织和岗位，因此初始管理员不在本表单分配组织或岗位。

### 4. 展示规则

- Tenant 名称、类型和有效时区为必填；Tenant 编码由服务端生成并在创建后只读。
- 初始管理员方式必须二选一。
- 现有用户方式只支持完整登录名精确查找；匹配后展示登录名、姓名和状态供确认。
- 新用户方式不显示密码字段，不允许自定义默认密码。
- 初始管理员身份固定选中且不可取消。
- 初始管理员必须在 Tenant 创建后立即有效；不允许设置未来生效或已过期的有效期。

### 5. 用户操作

#### OP-01 精确查找现有用户

##### 显示条件

- 已选择“使用现有用户”。

##### 可操作条件

- 已输入完整登录名。

##### 操作过程

1. 点击“查找用户”。
2. 页面进入查询状态并禁止重复查询。
3. 匹配成功后展示最小确认信息。
4. 未匹配或用户不可用时显示明确结果。

##### 成功结果

- 用户可确认该现有用户作为初始管理员。

##### 失败结果

- 不自动推荐相似用户，不允许继续创建。

#### OP-02 创建 Tenant

##### 显示条件

- 当前用户具有创建 Tenant 权限。

##### 可操作条件

- Tenant 和初始管理员信息完整、合法，现有用户已确认或新用户信息校验通过。

##### 操作过程

1. 用户点击“创建”。
2. 页面执行完整表单校验。
3. 提交期间锁定全部创建操作。
4. 成功后进入新 Tenant 详情或返回列表并定位新 Tenant。
5. 失败后保留输入并显示整体失败原因。

##### 成功结果

- 列表新增一个 `ACTIVE` Tenant。
- 指定用户成为该 Tenant 的有效初始管理员。

##### 失败结果

- 页面不得表现为 Tenant 已部分创建。
- 编码冲突、用户无效或关联失败均允许修正后重试。

### 6. 业务规则

- 引用 `BR-M02-F02-01` 至 `BR-M02-F02-06`。
- 创建新用户时同时引用 `BR-M05-F02-01`、`BR-M05-F02-04`、`BR-M05-F02-09` 至 `BR-M05-F02-11`。
- `UIR-M02-F02-01`：不得显示 Tenant 上级选择控件。
- `UIR-M02-F02-02`：不得显示自定义初始密码输入控件，也不得提交自定义密码。
- `UIR-M02-F02-03`：初始管理员必须作为 Tenant 创建表单的必填组成部分。

### 7. 状态与交互规则

- Editing：允许编辑表单。
- SearchingUser：现有用户查询处理中，禁止提交创建。
- UserConfirmed：展示已确认用户并允许更换。
- Processing：创建处理中，整个表单不可重复提交。
- Completed：展示完整成功结果。
- Failed：保留输入，不展示部分成功状态。

### 8. 状态与操作矩阵

| 初始管理员状态 | 页面显示 | 创建操作 | 是否可操作 |
|---|---|---|---|
| 未选择方式 | 方式选择 | 创建 | 否 |
| 现有用户未确认 | 精确查找区域 | 创建 | 否 |
| 现有有效用户已确认 | 用户确认信息 | 创建 | 表单合法时可用 |
| 新用户信息合法 | 新用户表单 | 创建 | 表单合法时可用 |
| 用户停用或已存在目标成员 | 错误说明 | 创建 | 否 |
| 提交中 | 处理中 | 创建 | 否 |

### 9. 约束

- Tenant 不能创建为 `DISABLED`。
- Tenant 编码由服务端生成且创建后不可修改。
- 不允许创建无初始管理员的 Tenant。
- 不显示或提交数据库隔离相关字段。
- 前端成功提示必须以整体创建成功结果为准。

### 10. 并发与重复操作要求

- 创建按钮连续点击只产生一次有效提交。
- 编码并发冲突时刷新列表并提示更换编码。
- 重试不得重复建立 Tenant 或初始管理员关系。

### 11. 权限与安全要求

- 仅集团超级管理员显示入口。
- 现有用户查找只展示身份确认所需最小信息。
- 不展示任何密码或密码验证信息。

### 12. 异常处理

| 场景 | 页面行为 |
|---|---|
| Tenant 编码重复 | 标记编码冲突，保留其他输入 |
| 时区无效 | 标记时区字段并阻止提交 |
| 现有用户不存在或已停用 | 显示不可用，不允许确认 |
| 新用户登录名已存在 | 提示改用现有用户方式 |
| 初始管理员建立失败 | 显示整体创建失败，不进入详情 |
| 网络结果不确定 | 不假定成功；重新查询 Tenant 列表确认 |

### 13. 验收标准

#### AC-M02-F02-01 现有用户方式

Given：现有用户为 `ACTIVE`，Tenant 编码和时区合法。

When：集团超级管理员创建 Tenant。

Then：Tenant 为 `ACTIVE` 且与其他 Tenant 平级，目标用户成为有效初始管理员。

#### AC-M02-F02-02 新用户方式

Given：新用户登录名未使用，表单合法。

When：创建 Tenant。

Then：用户、Tenant、成员及初始管理员整体创建成功；页面未提交自定义密码。

#### AC-M02-F02-03 整体失败

Given：初始管理员无效或关联建立失败。

When：提交创建。

Then：页面显示整体失败，不展示无管理员 Tenant 或孤立用户已创建。

#### AC-M02-F02-04 重复提交

Given：表单已满足提交条件。

When：用户连续点击创建。

Then：页面只处理一次有效提交，不产生重复 Tenant。

Tenant 编辑表单

## M02-F04 启用或停用 Tenant

### 1. 功能需求

- 集团超级管理员停用 `ACTIVE` Tenant 或启用 `DISABLED` Tenant。
- 状态变更前显示影响确认；成功后立即刷新列表和详情。

### 2. 进入条件

- 当前用户为集团超级管理员。
- 目标 Tenant 存在。

### 3. 页面内容

```text
Tenant 状态操作
├── 当前状态
├── 启用或停用入口
├── 影响说明
├── 确认操作
└── 结果反馈
```

### 4. 展示规则

- `ACTIVE` 显示“停用”，`DISABLED` 显示“启用”。
- 停用确认说明：成员将不能进入该 Tenant，历史信息不会删除。
- 启用确认说明：启用要求至少存在一名立即有效的 Tenant 管理员，且不会自动启用已停用成员。
- Tenant 管理员和普通用户不显示状态操作。

### 5. 用户操作

#### OP-01 停用 Tenant

##### 显示条件

- 目标 Tenant 为 `ACTIVE`。

##### 可操作条件

- 当前用户为集团超级管理员。

##### 操作过程

1. 用户点击“停用”。
2. 页面展示影响确认。
3. 确认后进入处理中状态。
4. 成功后状态更新为 `DISABLED` 并移出可切换 Tenant 集合。
5. 失败后刷新目标 Tenant 最新状态。

##### 成功结果

- Tenant 标记为停用，历史数据继续可在授权管理场景查看。

##### 失败结果

- 显示服务端原因，页面以刷新后的状态为准。

#### OP-02 启用 Tenant

##### 显示条件

- 目标 Tenant 为 `DISABLED`。

##### 可操作条件

- 当前用户为集团超级管理员。

##### 操作过程

1. 用户点击“启用”并确认。
2. 页面提交目标状态并禁止重复操作。
3. 成功后刷新 Tenant；失败后展示原因。

##### 成功结果

- Tenant 变为 `ACTIVE`。

##### 失败结果

- 无有效 Tenant 管理员时保持 `DISABLED` 并提示先处理管理员。

### 6. 业务规则

- 引用 `BR-M02-F04-01` 至 `BR-M02-F04-05`。
- `UIR-M02-F04-01`：状态按钮必须由服务端当前状态决定。

### 7. 状态与交互规则

- Ready：显示与当前状态相反的操作。
- Confirming：显示影响说明。
- Processing：禁用全部状态操作。
- Completed：刷新状态及可访问 Tenant 数据。
- Conflict：刷新最新状态，不沿用旧按钮。

### 8. 状态与操作矩阵

| 当前状态 | 页面操作 | 成功后状态 | 是否可操作 |
|---|---|---|---|
| ACTIVE | 停用 | DISABLED | 集团超级管理员可操作 |
| DISABLED 且有有效管理员 | 启用 | ACTIVE | 集团超级管理员可操作 |
| DISABLED 且无有效管理员 | 启用 | 保持 DISABLED | 服务端拒绝 |
| 状态请求处理中 | 处理中 | 未确定 | 否 |

### 9. 约束

- 状态操作不得删除 Tenant 或其成员、组织、岗位和历史信息。
- 启用不得自动启用成员。
- 停用成功后不得继续将该 Tenant 显示为可进入 Tenant。

### 10. 并发与重复操作要求

- 同一目标状态重复提交只显示一次有效结果。
- 并发冲突后刷新目标状态和版本。
- 网络结果不确定时先查询最新状态再允许重试。

### 11. 权限与安全要求

- 仅集团超级管理员显示状态操作。
- 状态结果以服务端校验为准。

### 12. 异常处理

| 场景 | 页面行为 |
|---|---|
| Tenant 不存在 | 移除无效详情并刷新列表 |
| 无有效管理员 | 启用失败，提示先建立有效管理员 |
| 状态已变化 | 刷新并展示最新状态 |
| 权限不足 | 隐藏入口并提示无权限 |
| 网络异常 | 不假定成功，重新查询状态 |

### 13. 验收标准

#### AC-M02-F04-01 正常停用

Given：Tenant 为 `ACTIVE`，用户为集团超级管理员。

When：确认停用。

Then：页面显示 `DISABLED`，该 Tenant 不再出现在可切换列表，历史信息未表现为删除。

#### AC-M02-F04-02 启用失败

Given：停用 Tenant 没有立即有效的 Tenant 管理员。

When：提交启用。

Then：页面提示失败，Tenant 保持 `DISABLED`。

#### AC-M02-F04-03 重复操作

Given：Tenant 已达到目标状态。

When：收到重复操作结果。

Then：页面保持当前状态，不产生重复成功记录或错误状态。

## M03 组织管理

### 2026-09-20 统一授权修订（优先于本节旧身份口径）

- 组织查询、详情、负责人候选、创建、编辑、移动和状态操作，分别以 `iam:organizations:view`、`iam:organizations:create`、`iam:organizations:update`、`iam:organizations:move`、`iam:organizations:change-status` Function，加上当前 Tenant/实体资源范围、有效成员关系和业务状态为准，不再要求 `is_tenant_admin=true`。
- 角色名称和管理员展示文案不构成准入；未获得对应 Function 的 Tenant 管理员也不得操作。
- 当前 Tenant、父组织、负责人、完整子树、状态、版本和跨 Tenant 禁止等边界不变；集团级 Tenant 切换沿用其既有特殊授权，本节修订不放宽集团/平台、Tenant 生命周期或管理员治理。

### 2026-09-18 用户确认的交互修订（优先于本节旧字段清单）

- 组织编码由服务端按统一规则生成；新建组织不展示、采集或提交 `org_code`。
- 编辑组织时编码只读展示，不作为可编辑字段，也不随更新请求提交。
- 从页面“新建组织”或“创建顶级组织”进入时，上级组织默认为空；不得回显 Tenant ID、当前节点 ID 或上次填写值。
- 上级组织只允许选择当前 Tenant 内的组织，选择后必须按组织名称稳定回显，不得把内部 ID 作为可见值。
- 从组织节点“新增下级”进入时，可明确预选该节点；用户仍可清空并创建顶级组织。

### 模块职责

在单个 Tenant 内维护组织树、组织负责人、层级和状态。组织仅表示部门结构，不作为 Tenant，也不在本期直接授予角色或权限。

### 功能清单

| ID | 功能 | 优先级 |
|---|---|---|
| M03-F01 | 查询组织 | P0 |
| M03-F02 | 创建组织 | P0 |
| M03-F03 | 更新组织信息 | P0 |
| M03-F04 | 调整组织层级 | P0 |
| M03-F05 | 启用或停用组织 | P0 |

## M03-F01 查询组织

### 1. 功能需求

- 以组织树作为管理主视图，选择节点后在同页展示组织详情。
- 支持按关键词、状态查询组织列表，用于快速定位节点。
- 展示负责人、层级、状态、排序和当前有效成员数量。

### 2. 进入条件

- 当前会话已确定授权范围内的目标 Tenant。
- 当前用户具有目标 Tenant 的 `iam:organizations:view` Function 和资源范围。

### 3. 页面内容

```text
组织管理页
├── Tenant 上下文
├── 关键词与状态筛选
├── 组织树
├── 组织详情
│   ├── 编码、名称、类型、上级
│   ├── 负责人、层级、排序
│   ├── 状态、有效成员数、备注
│   └── 更新时间
└── 创建、编辑、调整上级、启用或停用
```

### 4. 展示规则

- 组织树只包含目标 Tenant 的组织。
- 节点按父子关系和排序显示；不得重复挂载。
- 停用组织仍显示并明确标记 `DISABLED`。
- 普通组织管理使用当前 Tenant；具备既有集团级 Tenant 切换能力的用户可切换有权管理的目标 Tenant。
- 当前无组织时显示空状态和“创建顶级组织”入口。

### 5. 用户操作

#### OP-01 筛选和定位组织

##### 显示条件

- 组织管理页加载完成。

##### 可操作条件

- 目标 Tenant 已确定。

##### 操作过程

1. 用户输入关键词或选择状态。
2. 页面查询匹配组织。
3. 用户选择结果后，组织树展开并定位目标节点。

##### 成功结果

- 目标组织被选中并展示详情。

##### 失败结果

- 保留筛选条件，显示失败或空结果。

#### OP-02 切换管理 Tenant

##### 显示条件

- 当前用户为集团超级管理员。

##### 可操作条件

- 目标 Tenant 可管理。

##### 操作过程

1. 用户选择目标 Tenant。
2. 清空上一 Tenant 的组织详情和筛选结果。
3. 加载目标 Tenant 的组织树。

##### 成功结果

- 页面仅展示目标 Tenant 组织。

##### 失败结果

- 不混合展示两个 Tenant 的组织。

### 6. 业务规则

- 引用 `BR-M03-F01-01` 至 `BR-M03-F01-04`。
- `UIR-M03-F01-01`：切换 Tenant 时必须清空原 Tenant 已选组织和可操作状态。
- `UIR-M03-F01-02`：停用节点不得从管理树中隐藏。

### 7. 状态与交互规则

- Loading：组织树和详情分别显示加载状态。
- Empty：显示暂无组织及允许的创建入口。
- Ready：显示组织树和选中节点详情。
- Error：不展示结构不完整的组织树，提供重新加载。
- Unauthorized：清空页面中的组织数据并阻止操作。

### 8. 状态与操作矩阵

| 页面状态 | 页面显示 | 主操作 | 是否可操作 |
|---|---|---|---|
| 无组织 | 空状态 | 创建顶级组织 | 有权限时可用 |
| 已选择 ACTIVE 组织 | 详情 | 创建下级组织 | 是 |
| 已选择 DISABLED 组织 | 详情和停用标识 | 启用 | 视 Tenant 与上级状态 |
| 查询失败 | 错误状态 | 重新加载 | 是 |

### 9. 约束

- 不得跨 Tenant 拼接组织树。
- 组织不存在时不得按同编码或名称替换为其他节点。
- 页面显示的成员数量以服务端当前统计为准。

### 10. 并发与重复操作要求

- 组织变化后重新加载树和当前详情。
- 快速切换 Tenant 或筛选条件时，仅展示最后一次有效请求结果。

### 11. 权限与安全要求

- 用户只能查询 `iam:organizations:view` Function 和资源范围覆盖的当前 Tenant。
- 未获得 `iam:organizations:view` 的用户不得进入组织管理页；不得按普通成员或管理员名称推断准入。
- 目标组织权限不得由页面参数自行判断。

### 12. 异常处理

| 场景 | 页面行为 |
|---|---|
| Tenant 或组织不存在 | 显示失效并刷新组织树 |
| 组织树结构异常 | 不渲染错误树，提示重新加载 |
| 权限不足 | 清空受限数据并退出页面 |
| 网络异常 | 保留 Tenant 上下文，提供重试 |

### 13. 验收标准

#### AC-M03-F01-01 正常组织树

Given：Tenant A 存在多级启用和停用组织。

When：具有查看 Function 的用户加载组织页。

Then：父子关系、排序和状态正确，且不包含其他 Tenant。

#### AC-M03-F01-02 Tenant 切换

Given：集团超级管理员正在查看 Tenant A。

When：切换管理目标为 Tenant B。

Then：Tenant A 的选中节点和操作状态被清空，只展示 Tenant B 组织。

#### AC-M03-F01-03 越权查询

Given：仅获 Tenant A 资源范围的用户尝试访问 Tenant B 组织。

When：页面发起加载。

Then：访问被阻止，不展示 Tenant B 数据。

## M03-F02 创建组织

### 1. 功能需求

- 在 `ACTIVE` Tenant 内创建顶级组织或指定组织的下级组织。
- 可设置组织名称、类型、负责人、排序和备注；组织编码由服务端生成。
- 新组织创建后默认 `ACTIVE`。

### 2. 进入条件

- 当前用户有权管理目标 Tenant。
- 目标 Tenant 为 `ACTIVE`。
- 创建下级组织时，所选上级组织为 `ACTIVE`。

### 3. 页面内容

```text
创建组织表单
├── 所属 Tenant（只读）
├── 上级组织（顶级时为空）
├── 组织名称、类型（编码由服务端生成）
├── 负责人
├── 排序、备注
└── 创建、取消
```

### 4. 展示规则

- 从组织节点执行“新增下级”时预填该节点为上级。
- 从页面主入口执行“创建顶级组织”时上级为空。
- 上级组织选择范围仅包括同一 Tenant 的 `ACTIVE` 组织。
- 负责人选择范围仅包括同一 Tenant 当前有效成员，也允许不设置。
- 所属 Tenant 和默认状态只读。

### 5. 用户操作

#### OP-01 创建组织

##### 显示条件

- 用户具有目标 Tenant 的组织创建权限。

##### 可操作条件

- Tenant 和上级状态有效；组织名称等必填信息合法，组织编码由服务端生成。

##### 操作过程

1. 用户填写表单并点击“创建”。
2. 页面完成必填和选择范围校验。
3. 创建处理中禁止重复提交。
4. 成功后关闭表单、刷新组织树并选中新组织。
5. 失败后保留输入并显示原因。

##### 成功结果

- 新组织出现在正确层级，状态为 `ACTIVE`。

##### 失败结果

- 不在树中插入临时成功节点；修正后可重试。

### 6. 业务规则

- 引用 `BR-M03-F02-01` 至 `BR-M03-F02-07`。
- `UIR-M03-F02-01`：负责人选择不得自动改变该成员组织归属。
- `UIR-M03-F02-02`：创建表单不得提供其他 Tenant 的上级或负责人。

### 7. 状态与交互规则

- Editing、Processing、Completed、Failed、ContextInvalid。
- Tenant 或上级状态失效时，表单进入不可提交状态并要求刷新。

### 8. 状态与操作矩阵

| 条件 | 上级选择 | 负责人选择 | 创建 |
|---|---|---|---|
| ACTIVE Tenant，创建顶级 | 为空 | 当前有效成员 | 是 |
| ACTIVE Tenant，ACTIVE 上级 | 已选上级 | 当前有效成员 | 是 |
| DISABLED Tenant | 不可用 | 不可用 | 否 |
| DISABLED 上级 | 不可用 | 不可用 | 否 |

### 9. 约束

- 编码在 Tenant 内唯一且创建后不可修改。
- 不得跨 Tenant 选择上级或负责人。
- 创建负责人关系不创建或修改成员归属。

### 10. 并发与重复操作要求

- 创建处理中禁止重复点击。
- 编码冲突时不添加重复节点。
- 上级或 Tenant 在提交时失效，应刷新组织树后再操作。

### 11. 权限与安全要求

- 用户仅可凭 `iam:organizations:create` 在授权覆盖的当前 Tenant 创建。
- 服务端拒绝后不得依靠本地判断强制插入节点。

### 12. 异常处理

| 场景 | 页面行为 |
|---|---|
| 编码重复 | 标记编码字段，保留其他输入 |
| 上级已停用或不存在 | 提示重新选择并刷新树 |
| 负责人无效 | 清除无效选择并重新加载候选成员 |
| 权限失效 | 关闭创建入口 |
| 网络异常 | 不假定创建成功，刷新后确认 |

### 13. 验收标准

#### AC-M03-F02-01 创建顶级组织

Given：目标 Tenant 为 `ACTIVE`，编码未使用。

When：具有创建 Function 的用户不选择上级并创建。

Then：新组织成为顶级节点且状态为 `ACTIVE`。

#### AC-M03-F02-02 创建下级组织

Given：上级组织为同 Tenant 的 `ACTIVE` 组织。

When：具有创建 Function 的用户创建下级组织。

Then：新节点出现在指定上级下。

#### AC-M03-F02-03 跨 Tenant 限制

Given：请求上下文中的上级或负责人属于其他 Tenant。

When：提交创建。

Then：操作失败，两个 Tenant 的数据均不变。

## M03-F03 更新组织信息

### 1. 功能需求

- 更新组织名称、类型、负责人、排序和备注。
- 编码、所属 Tenant、上级组织和状态只读。

### 2. 进入条件

- 当前用户有权管理目标组织。
- 目标组织存在。

### 3. 页面内容

```text
组织编辑表单
├── 只读：所属 Tenant、组织编码、上级、状态
├── 可编辑：名称、类型、负责人、排序、备注
└── 保存、取消
```

### 4. 展示规则

- 负责人允许清空。
- 可选负责人仅为同 Tenant 当前有效成员。
- `DISABLED` 组织可修改名称、类型、排序和备注；可清空已有负责人，但不能设置新的负责人。
- 调整上级必须使用 M03-F04，不在本表单操作。

### 5. 用户操作

#### OP-01 保存组织信息

##### 显示条件

- 用户具有组织更新权限。

##### 可操作条件

- 表单有修改且校验通过。

##### 操作过程

1. 用户编辑并保存。
2. 页面校验不可变字段和负责人有效性。
3. 保存期间禁止重复提交。
4. 成功后刷新组织树节点和详情。
5. 失败后保留输入并显示原因。

##### 成功结果

- 组织信息更新，层级和状态不变。

##### 失败结果

- 冲突或负责人无效时不覆盖服务端当前数据。

### 6. 业务规则

- 引用 `BR-M03-F03-01` 至 `BR-M03-F03-06`。
- `UIR-M03-F03-01`：不得在普通编辑表单中修改上级。

### 7. 状态与交互规则

- Loading、Editing、Processing、Completed、Conflict。
- 组织状态在编辑期间变化时，按最新状态重新决定可编辑项。

### 8. 状态与操作矩阵

| 组织状态 | 可编辑项 | 负责人操作 | 保存 |
|---|---|---|---|
| ACTIVE | 名称、类型、负责人、排序、备注 | 设置或清空 | 是 |
| DISABLED | 名称、类型、排序、备注 | 仅允许清空 | 是 |
| 已失效或无权限 | 无 | 无 | 否 |

### 9. 约束

- 不得修改组织编码、Tenant、上级或状态。
- 更新负责人不改变成员组织归属。
- 更新完整成功或完整失败。

### 10. 并发与重复操作要求

- 旧版本保存失败后提示重新加载。
- 保存过程中禁止重复提交。

### 11. 权限与安全要求

- 用户仅可凭 `iam:organizations:update` 更新授权覆盖的当前 Tenant 组织。
- 页面候选成员不能包含其他 Tenant 成员。

### 12. 异常处理

| 场景 | 页面行为 |
|---|---|
| 组织不存在 | 关闭编辑并刷新树 |
| 负责人无效 | 清除选择并提示重新选择 |
| 修改不可变字段 | 阻止保存 |
| 版本冲突 | 保留输入，提示重新加载 |
| 权限不足 | 关闭操作入口 |

### 13. 验收标准

#### AC-M03-F03-01 正常更新

Given：目标组织为 `ACTIVE`，负责人属于同 Tenant 且当前有效。

When：更新名称和负责人。

Then：信息更新，编码、Tenant、上级和状态不变。

#### AC-M03-F03-02 停用组织限制

Given：目标组织为 `DISABLED`。

When：具有更新 Function 的用户尝试设置新负责人。

Then：页面不允许提交，原负责人关系不被替换。

#### AC-M03-F03-03 并发冲突

Given：组织已被其他管理员更新。

When：基于旧数据保存。

Then：提示冲突，不覆盖新数据。

## M03-F04 调整组织层级

### 1. 功能需求

- 将目标组织及其全部下级整体移动到同一 Tenant 的新上级下。
- 允许将组织调整为顶级组织。
- 不改变成员归属、负责人和节点状态。

### 2. 进入条件

- 当前用户有权管理目标 Tenant。
- 目标组织存在。
- 新上级为空或为同 Tenant 的 `ACTIVE` 组织。

### 3. 页面内容

```text
调整组织上级
├── 目标组织及当前上级
├── 下级组织影响提示
├── 新上级组织选择
├── 调整为顶级组织选项
└── 确认、取消
```

### 4. 展示规则

- 新上级候选只显示同 Tenant 的 `ACTIVE` 组织。
- 目标自身及全部下级不得成为候选上级。
- 当前上级不得作为需要重复选择的有效变更。
- 明确提示全部下级将随目标组织整体移动。

### 5. 用户操作

#### OP-01 确认调整层级

##### 显示条件

- 用户具有层级调整权限。

##### 可操作条件

- 已选择合法的新上级或顶级位置，且与当前层级不同。

##### 操作过程

1. 用户选择新上级并确认。
2. 页面显示影响范围并要求最终确认。
3. 提交期间禁止重复移动。
4. 成功后重新加载完整组织树并定位目标组织。
5. 失败后刷新树并显示原因。

##### 成功结果

- 目标及其完整子树出现在新位置。

##### 失败结果

- 页面不局部拼接可能错误的树结构。

### 6. 业务规则

- 引用 `BR-M03-F04-01` 至 `BR-M03-F04-05`。
- `UIR-M03-F04-01`：层级调整成功后必须重新加载完整组织树。

### 7. 状态与交互规则

- Selecting、Confirming、Processing、Completed、Conflict、InvalidTarget。

### 8. 状态与操作矩阵

| 新位置 | 页面显示 | 确认 | 是否可操作 |
|---|---|---|---|
| 同 Tenant ACTIVE 上级 | 新层级预期 | 调整 | 是 |
| 顶级 | 顶级位置 | 调整 | 是 |
| 自身或下级 | 非法提示 | 调整 | 否 |
| 其他 Tenant 或 DISABLED 上级 | 不作为候选 | 调整 | 否 |
| 当前上级 | 无变化 | 调整 | 否 |

### 9. 约束

- 不支持跨 Tenant 移动。
- 不通过修改组织信息接口改变上级。
- 移动不得修改负责人、成员归属或状态。

### 10. 并发与重复操作要求

- 移动处理中禁止再次操作。
- 层级冲突后必须刷新完整树。
- 重复移动到当前位置不展示为新变更。

### 11. 权限与安全要求

- 即使集团超级管理员也不得跨 Tenant 移动。
- 候选过滤不能替代服务端最终校验。

### 12. 异常处理

| 场景 | 页面行为 |
|---|---|
| 新上级失效 | 提示重新选择并刷新树 |

## M05-F07 维护成员组织归属

### 1. 功能需求

- 查询、新增、更新和结束成员组织归属。
- 一个成员可归属多个组织，但同一时点最多一个主要组织。
- 保留并只读展示已结束历史归属。

### 2. 进入条件

- 当前用户有权管理目标成员所属 Tenant。
- 新增或更新时成员为 `ACTIVE`，目标组织同 Tenant 且为 `ACTIVE`。

### 3. 页面内容

```text
成员组织归属
├── 当前主要组织
├── 当前辅助组织
├── 未来生效归属
├── 历史归属
└── 新增、编辑、设为主要、结束
```

归属展示：组织编码、名称、是否主要、有效开始、有效结束、当前是否有效、状态、备注和更新时间。

### 4. 展示规则

- 当前有效、未来生效、已结束记录分组展示。
- 主要组织明确标识；没有主要组织时显示“未设置”。
- 已结束记录不显示编辑、设为主要或恢复入口。
- 目标组织候选仅显示同 Tenant 的 `ACTIVE` 组织。
- 有效期按所属 Tenant 时区展示并标明时区。
- 仅当前有效归属可设置为主要组织。

### 5. 用户操作

#### OP-01 新增或更新组织归属

##### 显示条件

- 用户具有成员组织归属维护权限。

##### 可操作条件

- 成员和目标组织为 `ACTIVE`；有效期合法且不重叠。

##### 操作过程

1. 用户选择组织、主要属性、有效期和备注。
2. 页面校验同组织已知有效期重叠及主要组织规则。
3. 提交期间禁止重复操作。
4. 成功后重新加载完整组织归属。
5. 失败后保留输入并展示原因。

##### 成功结果

- 归属新增或更新；设为主要时原主要组织自动变为辅助组织。

##### 失败结果

- 不在页面产生重叠记录或两个主要组织。

#### OP-02 结束组织归属

##### 显示条件

- 目标归属尚未结束。

##### 可操作条件

- 用户有维护权限，结束时间合法。

##### 操作过程

1. 用户选择结束时间。
2. 页面展示结束后不自动创建其他主要组织的提示。
3. 确认后提交并等待结果。
4. 成功后重新加载全部归属。

##### 成功结果

- 归属在指定时间结束并保留为历史记录。

##### 失败结果

- 关系保持原状态，显示失败原因。

### 6. 业务规则

- 引用 `BR-M05-F07-01` 至 `BR-M05-F07-08`。
- `UIR-M05-F07-01`：已结束归属只读，重新归属必须新增记录。
- `UIR-M05-F07-02`：主要组织切换成功后必须重新加载所有组织归属。

### 7. 状态与交互规则

- Loading、Empty、Editing、Processing、Completed、Conflict、HistoryReadOnly。

### 8. 状态与操作矩阵

| 归属状态 | 页面显示 | 可用操作 | 是否可操作 |
|---|---|---|---|
| 当前有效辅助组织 | 辅助标识 | 编辑、设为主要、结束 | 是 |
| 当前有效主要组织 | 主要标识 | 编辑、结束 | 是 |
| 未来生效 | 未生效标识 | 编辑、结束 | 是；不得设为当前主要 |
| 已结束 | 历史标识 | 查看 | 否 |
| 成员或组织停用 | 不可维护提示 | 查看 | 否 |

### 9. 约束

- 成员与组织必须属于同一 Tenant。
- 同一成员与同一组织的有效期不得重叠。
- 同一时点最多一个主要组织。
- 允许成员没有主要组织。

### 10. 并发与重复操作要求

- 相同归属重复提交不得产生重叠记录。
- 并发设置主要组织后必须保证最多一个主要组织。
- 版本冲突、组织停用或成员停用时刷新完整归属和候选。

### 11. 权限与安全要求

- Tenant 管理员只可维护当前 Tenant 成员与组织关系。
- 候选列表不得包含其他 Tenant 组织。
- 页面校验不替代服务端归属与有效期校验。

### 12. 异常处理

| 场景 | 页面行为 |
|---|---|
| 成员或组织已停用 | 禁止新增或更新并刷新状态 |
| 有效期重叠 | 标记有效期并显示冲突归属 |
| 并发主要组织冲突 | 重新加载全部归属，展示最终主要组织 |
| 历史记录被编辑 | 阻止提交 |
| 跨 Tenant 数据 | 拒绝显示为可选项 |
| 网络异常 | 不假定成功，重新查询关系 |

### 13. 验收标准

#### AC-M05-F07-01 新增辅助组织

Given：成员和组织均为同 Tenant 的 `ACTIVE` 对象，且有效期不重叠。

When：新增辅助组织归属。

Then：归属成功，原主要组织不变。

#### AC-M05-F07-02 切换主要组织

Given：成员当前主要组织为 A，当前有效辅助组织为 B。

When：将 B 设为主要。

Then：B 成为唯一主要组织，A 保留为辅助组织。

#### AC-M05-F07-03 历史保护

Given：某组织归属已经结束。

When：尝试编辑或恢复该记录。

Then：页面不提供入口或操作被拒绝；历史记录不变。

#### AC-M05-F07-04 重复与并发

Given：相同归属被重复提交，或不同归属被并发设为主要。

When：请求完成。

Then：不存在有效期重叠，且最多一个当前有效主要组织。

## M06 登录与 Tenant 上下文

### 模块职责

完成登录，并为每个已登录用户确定唯一当前 Tenant。用户只能选择本人当前可进入的 Tenant；切换 Tenant 后，所有 Tenant 内页面均使用新的上下文。

### 功能清单

| ID | 功能 | 优先级 |
|---|---|---|
| M06-F01 | 用户登录 | P0 |
| M06-F02 | 登录后选择 Tenant | P0 |
| M06-F03 | 切换当前 Tenant | P0 |
| M06-F04 | 用户退出 | P0 |

## M06-F01 用户登录

### 1. 功能需求

- 用户使用登录名和密码登录。
- 页面展示当前集团公开信息。
- 登录成功后，根据返回状态直接进入有效默认 Tenant、唯一可用 Tenant，或进入 Tenant 选择页。
- 身份验证失败时不区分登录名不存在和密码错误。

### 2. 进入条件

- 当前用户未登录。
- 集团公开信息允许加载失败后单独重试，不阻止登录表单本身显示。

### 3. 页面内容

```text
登录页
├── 集团 Logo、名称、简称、平台展示名称
├── 登录名
├── 密码
├── 登录按钮
└── 加载与错误反馈
```

### 4. 展示规则

- 登录名和密码为必填。
- 密码默认不可见，允许用户主动切换可见性。
- 登录失败统一显示身份验证失败，不提示账号是否存在。
- 登录结果为 `AUTHENTICATED` 时进入当前 Tenant 的系统首页。
- 登录结果为 `TENANT_SELECTION_REQUIRED` 时进入 M06-F02。
- 没有可进入 Tenant 时停留在登录页，显示“当前没有可用 Tenant”。
- 首次登录修改初始密码属于第三组；如返回对应受限登录状态，只允许跳转至第三组提供的密码修改页，不进入业务页面。

### 5. 用户操作

#### OP-01 登录

##### 显示条件

- 用户未登录。

##### 可操作条件

- 登录名和密码均已填写，当前无登录请求处理中。

##### 操作过程

1. 用户填写登录名和密码并点击“登录”。
2. 页面立即进入处理中状态。
3. 成功后按登录状态进入当前 Tenant、Tenant 选择页或受限密码修改页。
4. 失败后恢复输入状态、清理密码输入并显示统一错误。

##### 成功结果

- 建立身份验证状态；进入业务页面前具有唯一当前 Tenant，或进入 Tenant 选择页。

##### 失败结果

- 不建立已登录页面状态，不泄露登录名是否存在。

### 6. 业务规则

- 引用 `BR-M06-F01-01` 至 `BR-M06-F01-07`。
- `UIR-M06-F01-01`：身份验证失败统一提示，不展示后台内部失败原因。
- `UIR-M06-F01-02`：未确定当前 Tenant 前不得进入 Tenant 内业务页面。
- `UIR-M06-F01-03`：本期不提供 Session 列表、过期时间或设备登录管理界面。

### 7. 状态与交互规则

- Idle：允许输入和提交。
- Processing：登录按钮不可重复点击。
- Authenticated：进入唯一当前 Tenant。
- TenantSelectionRequired：仅允许选择 Tenant 或退出。
- Failed：显示统一错误并允许重试。
- NoAvailableTenant：显示无可用 Tenant，不建立业务上下文。

### 8. 状态与操作矩阵

| 登录结果 | 页面显示 | 主操作 | 是否可进入业务页 |
|---|---|---|---|
| 凭证无效或用户停用 | 统一登录失败 | 重新登录 | 否 |
| 无可进入 Tenant | 无可用 Tenant | 重新登录或退出 | 否 |
| 唯一有效 Tenant | 系统首页 | 无 | 是 |
| 多 Tenant 且默认项有效 | 默认 Tenant 首页 | 无 | 是 |
| 多 Tenant 且无有效默认项 | Tenant 选择页 | 选择 Tenant | 否 |
| 初始密码受限状态 | 密码修改页 | 修改初始密码 | 否 |

### 9. 约束

- 仅支持登录名和密码。
- 登录页不得允许用户指定目标 Tenant 绕过成员校验。
- 密码不出现在成功结果、日志信息或错误详情中。
- 本 PRD 不实现密码修改页面。

### 10. 并发与重复操作要求

- 登录处理中禁止重复提交。
- 登录校验期间用户、成员或 Tenant 失效时，不进入业务页。
- 重复登录不创建任何用户或成员关系。

### 11. 权限与安全要求

- 登录前仅允许访问集团公开信息、登录及必要的受限密码修改流程。
- 失败信息不得帮助枚举用户。
- 前端不得以本地保存的 Tenant 判断代替服务端返回的可进入集合。

### 12. 异常处理

| 场景 | 页面行为 |
|---|---|
| 登录名不存在或密码错误 | 统一显示“登录名或密码错误” |
| 用户已停用 | 不进入系统，使用不泄露额外身份信息的失败提示 |
| 无有效 Tenant | 显示当前没有可用 Tenant |
| 默认 Tenant 失效 | 有其他 Tenant 时进入选择页 |
| 网络异常 | 清理处理中状态，不假定登录成功 |
| 集团公开信息失败 | 品牌区显示独立错误，登录表单仍可操作 |

### 13. 验收标准

#### AC-M06-F01-01 单 Tenant 登录

Given：凭证有效且用户只有一个可进入 Tenant。

When：提交登录。

Then：直接进入该 Tenant，当前 Tenant 唯一明确。

#### AC-M06-F01-02 多 Tenant 无默认项

Given：凭证有效，存在多个可进入 Tenant 且无有效默认项。

When：提交登录。

Then：进入 Tenant 选择页，尚不进入业务页面。

#### AC-M06-F01-03 身份保密

Given：一次使用不存在登录名，另一次使用错误密码。

When：分别登录。

Then：页面使用同类失败提示，不区分具体原因。

#### AC-M06-F01-04 重复提交

Given：登录请求正在处理。

When：用户再次点击登录。

Then：不发起第二次有效操作。

## M06-F02 登录后选择 Tenant

### 1. 功能需求

- 凭证验证成功但未确定 Tenant 时，从服务端返回的可进入 Tenant 中选择一个。
- 可在选择时将目标 Tenant 设为默认 Tenant。
- 选择成功后进入目标 Tenant 系统首页。

### 2. 进入条件

- 登录状态为 `TENANT_SELECTION_REQUIRED`。
- 存在至少一个服务端返回的可选择 Tenant。

### 3. 页面内容

```text
Tenant 选择页
├── 当前用户提示
├── 可进入 Tenant 列表
│   ├── Logo、名称、编码、类型
│   └── 时区、默认标识
├── 设为默认 Tenant
├── 进入 Tenant
└── 退出
```

### 4. 展示规则

- 只展示本次登录结果中的可进入 Tenant。
- Tenant 以平级列表展示，不构造层级关系。
- 已标记为默认但当前无效的 Tenant 不显示为可选项。
- 用户必须明确选择一项后才可继续。
- 设置默认为可选，不预设改变用户原默认项。

### 5. 用户操作

#### OP-01 选择并进入 Tenant

##### 显示条件

- 页面存在可选择 Tenant。

##### 可操作条件

- 已选择一个 Tenant，当前无提交处理中。

##### 操作过程

1. 用户选择 Tenant，可选择“设为默认”。
2. 点击“进入”。
3. 页面进入处理中状态。
4. 服务端重新校验目标 Tenant 和成员有效性。
5. 成功后进入目标 Tenant；失败后刷新可选择集合或要求重新登录。

##### 成功结果

- 登录状态为 `AUTHENTICATED`，当前 Tenant 唯一。
- 选择设为默认时，该 Tenant 成为唯一默认项。

##### 失败结果

- 不进入业务页，不自动选择其他 Tenant。

#### OP-02 退出选择流程

##### 显示条件

- 处于 Tenant 选择页。

##### 可操作条件

- 无选择提交正在处理。

##### 操作过程

1. 用户点击退出。
2. 结束当前登录状态。
3. 返回登录页。

##### 成功结果

- 不保留当前 Tenant。

##### 失败结果

- 清理本地受保护页面状态并返回登录页。

### 6. 业务规则

- 引用 `BR-M06-F02-01` 至 `BR-M06-F02-05`。
- `UIR-M06-F02-01`：未选择 Tenant 时不得开放进入操作。
- `UIR-M06-F02-02`：选择失败不得自动切换到列表中的其他 Tenant。

### 7. 状态与交互规则

- Loading、Ready、Processing、TargetInvalid、Empty、Unauthenticated。

### 8. 状态与操作矩阵

| 页面状态 | 页面显示 | 主操作 | 是否可操作 |
|---|---|---|---|
| 有候选但未选择 | Tenant 列表 | 进入 | 否 |
| 已选择有效候选 | 选中项 | 进入 | 是 |
| 提交中 | 处理中 | 进入 | 否 |
| 目标已失效 | 失效提示 | 重新选择 | 是 |
| 无候选 | 无可用 Tenant | 退出 | 是 |
| 登录状态失效 | 重新登录提示 | 返回登录 | 是 |

### 9. 约束

- 不允许手工输入 Tenant 标识。
- 一个登录状态只能选择一个当前 Tenant。
- 集团超级管理员同样只能选择本人具有有效成员身份的 Tenant。

### 10. 并发与重复操作要求

- 进入操作处理中禁止重复提交。
- 并发选择不同 Tenant 时，只接受服务端确认的最终上下文。
- 目标状态变化导致失败时刷新候选列表。

### 11. 权限与安全要求

- 仅允许为当前登录用户选择 Tenant。
- 不展示未授权 Tenant 或其成员信息。
- 候选列表不作为永久授权缓存。

### 12. 异常处理

| 场景 | 页面行为 |
|---|---|
| 目标 Tenant 或成员已失效 | 保持选择页，移除或标记失效项 |
| 登录状态无效 | 返回登录页 |
| 设置默认冲突 | 使用服务端最终默认项并刷新列表 |
| 网络异常 | 保持未进入状态，允许重试 |

### 13. 验收标准

#### AC-M06-F02-01 正常选择

Given：用户处于选择状态且 Tenant A 当前有效。

When：选择 Tenant A 并进入。

Then：进入 Tenant A，当前 Tenant 唯一。

#### AC-M06-F02-02 设置默认

Given：用户有多个可进入 Tenant。

When：选择 Tenant B 并设为默认。

Then：进入 Tenant B，Tenant B 成为唯一默认项。

#### AC-M06-F02-03 目标失效

Given：Tenant A 在列表加载后被停用。

When：用户选择 Tenant A。

Then：进入失败，不自动进入其他 Tenant，并刷新候选状态。

## M06-F03 切换当前 Tenant

### 1. 功能需求

- 已登录用户从全局 Tenant 切换入口切换到本人另一个可进入 Tenant。
- 可将目标 Tenant 同时设为默认 Tenant。
- 切换成功后清除原 Tenant 页面数据，并重新进入新 Tenant 上下文。

### 2. 进入条件

- 当前登录状态为 `AUTHENTICATED`。
- 当前用户存在其他可进入 Tenant。

### 3. 页面内容

```text
全局 Tenant 切换入口
├── 当前 Tenant 名称
├── 可进入 Tenant 列表
├── 默认 Tenant 标识
├── 设为默认选项
└── 切换结果反馈
```

### 4. 展示规则

- 始终明确显示当前 Tenant。
- 候选列表仅包含本人可进入 Tenant；当前 Tenant 可显示但不可产生重复切换。
- 只有一个可进入 Tenant 时，可隐藏展开式切换入口，但仍显示当前 Tenant。
- Tenant 切换后，页面标题、数据、组织、岗位、成员和后续权限展示均不得保留上一 Tenant 内容。

### 5. 用户操作

#### OP-01 切换 Tenant

##### 显示条件

- 存在其他可进入 Tenant。

##### 可操作条件

- 目标 Tenant 与当前 Tenant 不同，且无切换请求处理中。

##### 操作过程

1. 用户选择目标 Tenant，可选择设为默认。
2. 页面提交切换并锁定再次切换。
3. 成功后清空旧 Tenant 页面状态，更新当前 Tenant，进入新 Tenant 首页。
4. 失败后保留原当前 Tenant，并显示原因。

##### 成功结果

- 当前 Tenant 和当前成员同时切换，原 Tenant 关系不变。
- 选择设为默认时，目标 Tenant 成为唯一默认项。

##### 失败结果

- 原当前 Tenant 和页面上下文保持可用；不得出现半切换状态。

### 6. 业务规则

- 引用 `BR-M06-F02-01` 至 `BR-M06-F02-06`。
- `UIR-M06-F03-01`：切换成功后必须清除所有旧 Tenant 业务页面状态。
- `UIR-M06-F03-02`：切换失败时不得清空原有效上下文。

### 7. 状态与交互规则

- Ready、Processing、Completed、TargetInvalid、Conflict、Unauthenticated。

### 8. 状态与操作矩阵

| 目标状态 | 页面行为 | 切换 | 结果 |
|---|---|---|---|
| 当前 Tenant | 保持当前 | 不提交 | 无变化 |
| 其他有效 Tenant | 显示候选 | 是 | 切换成功 |
| 已停用、成员失效或过期 | 不作为有效候选/服务端拒绝 | 否 | 保留原 Tenant |
| 切换处理中 | 锁定入口 | 否 | 等待结果 |
| 登录失效 | 清理受保护状态 | 否 | 返回登录页 |

### 9. 约束

- 切换不得修改用户、成员、组织或岗位关系。
- 切换失败不得丢失原当前 Tenant。
- 不通过地址参数直接切换 Tenant。

### 10. 并发与重复操作要求

- 切换处理中禁止再次提交。
- 两个并发切换结果只采用服务端最终确认的单一当前 Tenant。
- 发生冲突后重新获取当前上下文和候选 Tenant。

### 11. 权限与安全要求

- 只能切换当前用户本人 Tenant。
- 新 Tenant 页面数据必须在切换成功后重新加载。
- 不在旧页面短暂展示新 Tenant 标识与旧 Tenant 数据的组合。

### 12. 异常处理

| 场景 | 页面行为 |
|---|---|
| 目标 Tenant 或成员失效 | 显示失败，保留原 Tenant，刷新候选 |
| 并发切换冲突 | 获取服务端最终当前 Tenant 并进入对应首页 |
| 网络异常 | 不假定切换成功，重新确认当前上下文 |
| 登录状态失效 | 清空受保护页面并返回登录页 |

### 13. 验收标准

#### AC-M06-F03-01 正常切换

Given：当前 Tenant 为 A，用户可进入 Tenant B。

When：切换到 Tenant B。

Then：当前 Tenant 和成员变为 B，旧 Tenant 页面数据被清除。

#### AC-M06-F03-02 切换失败

Given：目标 Tenant 在提交时已失效。

When：用户切换。

Then：页面保留 Tenant A，不出现半切换状态。

#### AC-M06-F03-03 并发切换

Given：同时发起到 Tenant B 和 C 的切换。

When：请求完成。

Then：页面最终只对应服务端确认的一个当前 Tenant。

## M06-F04 用户退出

### 1. 功能需求

- 已验证身份的用户可退出当前登录。
- 退出后清除当前用户、Tenant、成员及受保护页面状态并返回登录页。
- 重复退出视为已退出，不展示异常业务状态。

### 2. 进入条件

- 当前处于 `AUTHENTICATED` 或 `TENANT_SELECTION_REQUIRED`。

### 3. 页面内容

```text
退出操作
├── 全局退出入口
├── 处理中状态
└── 登录页
```

### 4. 展示规则

- 已登录页面和 Tenant 选择页均提供退出入口。
- 退出处理中入口不可重复点击。
- 退出完成后不再显示任何受保护数据。

### 5. 用户操作

#### OP-01 退出

##### 显示条件

- 当前存在已验证登录状态。

##### 可操作条件

- 当前无退出请求处理中。

##### 操作过程

1. 用户点击退出。
2. 页面进入处理中状态。
3. 完成后清空当前用户、Tenant、成员和受保护页面状态。
4. 返回登录页并重新加载集团公开信息。

##### 成功结果

- 原登录状态不能继续访问受保护页面。

##### 失败结果

- 对已明确失效的登录状态仍按已退出处理；其他不确定错误不得继续展示受保护页面。

### 6. 业务规则

- 引用 `BR-M06-F03-01` 至 `BR-M06-F03-03`。
- `UIR-M06-F04-01`：退出后必须清除所有 Tenant 相关页面状态。

### 7. 状态与交互规则

- Ready、Processing、Completed、AlreadyLoggedOut。

### 8. 状态与操作矩阵

| 当前状态 | 主操作 | 结果 |
|---|---|---|
| AUTHENTICATED | 退出 | 返回登录页 |
| TENANT_SELECTION_REQUIRED | 退出 | 返回登录页 |
| UNAUTHENTICATED | 无或重复退出 | 保持登录页 |
| 退出处理中 | 无 | 禁止重复提交 |

### 9. 约束

- 退出不修改默认 Tenant、用户、成员、组织或岗位状态。
- 退出后不得使用原页面状态继续操作。
- 不提供退出其他设备或全部登录功能。

### 10. 并发与重复操作要求

- 重复退出幂等。
- 退出与切换并发时，以退出后的未登录状态为最终页面状态。

### 11. 权限与安全要求

- 用户只能退出自己的当前登录。
- 退出后访问受保护页面必须返回登录页。

### 12. 异常处理

| 场景 | 页面行为 |
|---|---|
| 已经退出 | 返回登录页，不显示错误业务状态 |
| 退出与切换并发 | 清除切换结果，保持未登录 |
| 退出后访问受保护页面 | 阻止访问并返回登录页 |
| 网络状态不确定 | 不继续展示敏感页面，重新确认登录状态 |

### 13. 验收标准

#### AC-M06-F04-01 正常退出

Given：用户已登录并处于某 Tenant。

When：点击退出。

Then：返回登录页，当前 Tenant 和受保护数据被清除。

#### AC-M06-F04-02 重复退出

Given：用户已经退出。

When：再次触发退出结果。

Then：保持登录页，不产生异常状态。

#### AC-M06-F04-03 与切换并发

Given：退出与 Tenant 切换同时发生。

When：退出成功。

Then：最终为未登录状态，不保留切换后的上下文。

# 5. 跨模块用户流程

## 5.1 创建 Tenant 并建立初始管理员

起点：集团超级管理员从 Tenant 管理页点击创建。

```text
填写 Tenant 信息
→ 选择现有用户或创建新用户
→ 填写成员信息
→ 确认初始管理员
→ 整体提交
→ 成功后进入 Tenant 详情
```

- 现有用户必须使用完整登录名精确确认。
- 新用户不提供密码输入，系统使用固定初始密码。
- 任一步骤失败时停留在创建页，不显示部分成功。
- 完成条件：Tenant 为 `ACTIVE`，并且存在立即有效的初始 Tenant 管理员。

## 5.2 员工入职并获得 Tenant 成员身份

起点：有权限管理员从成员页点击新增。

```text
选择目标 Tenant
→ 选择新用户或现有用户
→ 填写成员资料与有效期
→ 可选分配组织和岗位
→ 整体提交
→ 查看成员详情
```

- Tenant 管理员目标 Tenant 固定为当前 Tenant。
- 组织和岗位均允许为空，但候选必须属于目标 Tenant 且为 `ACTIVE`。
- 完成条件：用户和成员建立成功；是否立即可进入还取决于成员有效期。

## 5.3 员工组织或岗位调整

起点：管理员进入成员详情的组织或岗位归属区。

```text
查看当前与历史归属
→ 新增或编辑目标归属
→ 必要时设为主要
→ 必要时结束旧归属
→ 重新加载完整归属
```

- 已结束历史记录不可改写。
- 同一时点最多一个主要组织和一个主要岗位。
- 完成条件：新关系有效且不重叠，历史关系完整保留。

## 5.4 用户登录并确定当前 Tenant

起点：用户打开登录页。

```text
加载集团公开信息
→ 输入登录名和密码
→ 登录验证
→ 直接进入唯一或默认 Tenant / 选择 Tenant
→ 建立唯一当前 Tenant
```

- 没有可进入 Tenant 时流程终止在登录页。
- 初始密码受限状态转交第三组密码修改流程。
- 完成条件：登录状态为 `AUTHENTICATED`，当前 Tenant 和成员唯一明确。

## 5.5 停用身份并终止访问资格

起点：有权限管理员从 Tenant、用户或成员详情发起停用。

```text
选择停用层级
→ 查看影响范围
→ 校验最后管理员与负责人保护
→ 确认停用
→ 刷新目标及关联状态
```

- 停用用户影响全部 Tenant；停用成员仅影响一个 Tenant；停用 Tenant 影响所有用户进入该 Tenant。
- 保护规则不满足时流程中断，不改变原状态。
- 完成条件：目标访问资格失效，未受影响关系保持原状，历史记录保留。

# 6. 全局前端规则

- `GUIR-001`：所有提交类操作在结果返回前必须禁止重复提交。
- `GUIR-002`：页面重新进入、刷新或操作完成后，以服务端最新状态为准。
- `GUIR-003`：无权限页面、字段和操作入口不得展示；直接访问时必须阻止继续操作。
- `GUIR-004`：前端隐藏或禁用不能替代服务端权限和业务校验。
- `GUIR-005`：失败操作不得表现为成功；网络结果不确定时必须重新查询目标状态。
- `GUIR-006`：版本冲突时不得静默覆盖新数据；应保留必要的本地输入并要求重新加载。
- `GUIR-007`：Tenant 管理员所有管理页面固定使用当前 Tenant，不提供可绕过的 Tenant 参数入口。
- `GUIR-008`：集团超级管理员切换管理目标 Tenant 时，必须清除原 Tenant 的列表、详情、候选项和未提交表单。
- `GUIR-009`：Tenant 一律平级展示，不设计 Tenant 树和父子关系。
- `GUIR-010`：时间有效性由服务端判断；成员及归属时间按所属 Tenant 时区展示、输入并标注时区。
- `GUIR-011`：`ACTIVE` 状态与“当前有效”必须区分展示，不能仅凭状态判断可进入或可归属。
- `GUIR-012`：登录名、Tenant 编码、组织编码和岗位编码创建后只读。
- `GUIR-013`：用户全局状态与 Tenant 成员状态必须分别显示和操作。
- `GUIR-014`：集团、Tenant、组织、岗位、用户、成员和历史归属均不提供删除入口。
- `GUIR-015`：停用不表现为删除；管理查询中仍应显示停用对象和历史关系。
- `GUIR-016`：列表查询必须处理 Loading、Empty、Error 和分页状态；筛选变化后回到第一页。
- `GUIR-017`：详情不存在或已失效时关闭旧详情并刷新来源列表或组织树。
- `GUIR-018`：创建和更新表单取消时，如存在未保存修改，应先确认是否放弃。
- `GUIR-019`：跨 Tenant 选择控件只显示当前用户有权管理且符合业务状态的候选对象。
- `GUIR-020`：不得显示、缓存到可见页面或回显密码及可还原密码的信息。
- `GUIR-021`：新用户初始密码不得由前端采集或提交，即使接口请求结构存在该字段。
- `GUIR-022`：接口返回的 Session 标识、过期信息及数据库隔离信息不进入本期页面功能。
- `GUIR-023`：服务端返回业务状态已变化时，页面必须刷新对应对象及受影响候选列表。
- `GUIR-024`：空数据必须显示明确空状态，不显示无意义空容器或伪造默认数据。
- `GUIR-025`：错误提示应说明失败原因或下一步可执行操作，但登录失败不得泄露账号是否存在。

# 2026-09-18 最新裁定：基础实体编码由系统生成

- 集团、Tenant、组织、岗位及 Tenant 成员的编码不再由用户填写，也不出现在创建请求或更新请求中；系统生成的成员显示名称同样不由更新接口回传。
- 服务端在实体创建成功后生成稳定且唯一的编码；后续编辑不允许变更。
- 前端可在列表、详情、删除确认和编辑态只读展示编码，但不得提供可编辑编码输入框。
- 本裁定覆盖本文全文中关于手工填写或回传 `group_code`、`tenant_code`、`org_code`、`position_code`、`tenant_user_code` 的旧描述。
