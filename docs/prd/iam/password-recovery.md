# IAM 忘记密码页候选需求

## 需求来源

- 当前用户要求：参考所附效果图设计忘记密码页面。
- 视觉参考：`docs/design/references/iam-password-recovery.png`。
- 参考图只用于“顶部品牌、居中单列找回表单、深色桌面画面”的构图证据，不继承 TMS 品牌、英文文案、具体验证码通道或后端行为。
- 已批准相邻页面：`UIDesign/baselines/iam-login/desktop-1440.png`，用于保持认证场景的品牌、颜色、控件与排版一致。

## 页面目标

为陆链控制台提供统一的未认证密码找回入口。当前阶段只形成可审核的桌面候选页面、表单校验和完整的本地状态反馈，不接入真实 IAM 服务。

## 候选范围

- 使用简体中文、现有 Design Token、共享 `AuthPageTemplate`、共享 `AuthBrand`、Element Plus 与 Iconify。
- 使用认证前独立布局，不显示登录后的 `AppShell`。
- 展示账号输入、发送验证码、返回登录三个明确动作。
- 空提交时展示字段错误并聚焦账号输入框。
- 提供提交中、已受理和可重试错误状态；按钮忙碌时保持几何并阻止重复提交。
- 提交完成提示必须保持通用，不确认账号是否存在。
- 在 `1366×768`、`1440×900`、`1920×1080` 三个桌面视口验证。

## 非目标与生产阻断项

- 不定义或接入找回 API、账号识别规则、验证码发送通道、验证码有效期、频率限制、锁定策略和后续重置步骤。
- 不推断“返回登录”的正式路由。
- 不创建 Production Binding，不接入生产路由，不写入 Approval Record，不更新已批准视觉基线。

## 验收

1. 页面与已批准登录页保持同一认证视觉系统，并保留参考图的顶部品牌和单列聚焦关系。
2. 空提交、有效提交、提交中、已受理、可重试错误和返回登录入口均有可观察反馈。
3. 所有提交结果使用通用文案，不泄露账号是否存在。
4. Preview 不产生业务网络请求，三个标准视口无横向溢出或关键内容裁切。
5. 页面状态保持 `reviewing`，只有用户明确批准后才登记为 `approved`。
