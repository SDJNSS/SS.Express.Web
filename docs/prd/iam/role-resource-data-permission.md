# IAM 角色、资源与数据权限（受控需求摘要）

> 来源：用户提供的《IAM-角色资源与数据权限-前端PRD.md》，2026-09-07 纳入项目受控来源。原始附件仅作为证据；本文件继续记录角色管理、功能权限、数据权限与角色分配依赖的业务边界。应用与权限资源已迁移到 `application-permission-resources.md`。

## 页面范围

本文件覆盖 PC Web 管理端两个 Menu 及其页内工作区：

1. **角色管理 Menu**：按目标 Tenant 查询、创建、编辑和启停自定义角色；角色列表、详情和编辑抽屉可进入角色功能权限，列表也可进入角色数据权限和角色分配 Page。三个 Page 不进入左侧菜单，其 API 操作作为各 Page 下的叶子 Function。
2. **用户与成员 Menu**：`/iam/members` 是唯一用户管理入口；管理员可在选定用户与 Tenant 上下文中分配或撤销角色，并只读查看该 Tenant 成员的有效 Function。用户仍不能被直接授予 Function，也不在此编辑数据权限。

角色功能权限按角色和 App 展示资源树；树节点以完整资源名称为唯一文本，复选框表达当前选择，资源编码、来源与异常等信息按需在详情区查看。保存完整选择集合，允许空集合。角色数据权限展示预注册数据域、关联资源和异常；按角色配置单一范围，CUSTOM 可选择同集团多个有效 Tenant，未配置等于无数据访问权。角色成员页固定以角色为主视角，查询一个角色的直接成员，支持添加或移除成员；成员管理身份不再混入该页。

M06“权限结果与授权判断”是公共 App Shell、路由、页面和业务数据面的横切行为，不建立管理员模拟或手工编辑计算结果的独立页面。它要求所有受保护页面覆盖 PermissionLoading、Denied、ScopeEmpty、ConfigurationError、Revoked 等安全状态。

## 用户与范围

- 普通用户只使用本人有效 App、Module、Menu、Page、Function 和服务端允许的数据，不进入权限管理页面。
- 单个用户不能直接分配功能权限或数据权限；用户权限只能通过角色获得。用户角色与权限页可以维护用户在选定 Tenant 下的角色关系，但 Function 结果固定只读，角色本身及其 Function 集合仍在角色管理中维护。
- Tenant 管理员仅管理当前 Tenant 的普通自定义角色，不得维护集团控制角色或受保护管理员身份，不显示 GROUP、CUSTOM。
- 集团超级管理员跨 Tenant 管理前必须明确选择目标 Tenant，可维护全局系统/资源，可配置 GROUP、CUSTOM，可任命或取消 Tenant 管理员。
- 页面入口、按钮和可维护状态以服务端权限及 `can_maintain` 为准；前端隐藏不替代服务端授权。

## 稳定规则

- 数据域和系统角色的稳定定义只读；App 与权限资源维护规则见独立受控 PRD。
- 系统、资源、角色只使用 `active` / `disabled`，页面显示“启用”/“停用”。
- 停用保留既有授权、配置和分配关系；父资源停用使分支当前无效，但不改变子节点直接状态。
- 功能权限使用精确授权：Module、Menu、Page 不自动授予任何后代；编辑勾选只以 `direct_resource_ids` 初始化，不能把 `effective_resource_ids` 反写为精确授权集合。
- `is_inherited` 仅为接口兼容字段，不参与授权状态或界面文案；`is_navigation_only` 仅表示为还原已授权资源路径而返回的祖先容器。
- 数据范围显示为本人、本人组织、本人组织及下级、当前 Tenant、集团、指定 Tenant。未配置相关域必须显示“无数据访问权”，不能回退为 Tenant 或全量。
- Tenant 管理员不能查看或提交 GROUP、CUSTOM；包含 GROUP/CUSTOM 的角色为集团控制角色。
- Tenant 管理员身份与普通角色分开显示和操作；任命不授予业务角色，取消不撤销普通角色，最后一名有效管理员不可取消。
- 角色批量分配/撤销全部成功或全部失败；普通撤销不能取消 Tenant 管理员身份。
- 保存、启停、授权、分配和撤销采用服务端确认的悲观反馈，提交中防重复；版本冲突不得静默覆盖。
- Tenant/系统切换时取消或忽略旧上下文结果；权限加载或数据范围解析失败时默认拒绝。
- 业务筛选不是授权边界；前端不拼接角色、Tenant、组织或成员集合扩大权限。

## 页面字段与主要操作

### 角色管理

- 查询条件：目标 Tenant、关键字、角色类型、状态、页码、页大小。
- 角色：编码、名称、类型、状态、说明、备注、排序、当前有效性、集团控制、可维护、版本、创建/更新时间。
- 创建录入 Tenant、编码、名称、说明、备注、排序。编辑允许修改最新版 `UpdateRole` 的全部参数：Tenant、编码、类型、状态、名称、说明、备注、排序，并携带 ID 和版本。
- 角色列表、详情和编辑抽屉均提供功能权限入口；列表另提供数据权限、角色成员入口。它们分别进入 `/iam/roles/function-permissions`、`/iam/roles/data-permissions`、`/iam/roles/assignments` 隐藏 Page，并通过查询参数保持角色上下文。功能权限入口和隐藏路由使用 `iam:roles:function-permissions:view`，保存使用 `iam:roles:function-permissions:update`；Page 编码不作为运行时门禁。

### 用户角色与权限

- 从 `/iam/members` 的用户行进入 `/iam/members/permissions?userId=...&tenantId=...`；页面 URL 不再以 `tenant_user_id` 作为业务主键。旧 `tenantUserId` 查询参数仅作为迁移期兼容输入，解析后立即替换为 `userId`。
- 角色页签先用 `QueryUserTenants(user_id)` 解析用户在所选 Tenant 下的 `tenant_user_id` 与 `member_version`，再展示直接角色、管理员身份和当前有效性。
- 具备对应 Function 权限时，可通过 `MemberRole/Assign` 与 `MemberRole/Revoke` 为该用户在当前 Tenant 分配或撤销角色；提交后重新加载服务端权威结果。
- Function 页签使用 `QueryMemberFunctionPermissions(tenant_user_id)`，按 App/Module/Menu/Page/Function 展示当前 Tenant 成员的有效权限及来源角色，始终只读，不提供 Function 直授权或保存入口。
- 数据权限功能当前搁置，不在该页恢复入口。

### 功能权限

- 按系统分组显示资源树；每个树节点只展示完整资源名称，不展示资源编码、“精确授权”或其他状态标签。名称允许换行，不得使用省略号隐藏关键内容。
- 复选框本身表达当前选择；资源编码、权限标识、来源、类型和异常原因仅在右侧详情区按需展示。
- 树保持父子独立勾选语义。点击父节点复选框时，前端将其解释为一次显式批量操作：勾选时逐项选中当前全部可维护且有效的子孙，取消时逐项取消这些子孙；用户随后仍可单独调整任意子项。
- 父级批量不构成后端继承，也不会自动覆盖未来新增资源。保存时父级及每个最终选中的子孙都必须逐项进入 `direct_resource_ids`。
- 提供“展开全部”“收起全部”；普通勾选不得重建树，必须保留用户已折叠分支和当前滚动位置。
- 资源树提供当前 App 范围的本地搜索，按资源名称、资源编码、权限标识、路由地址、请求方法和 API Path 做不区分大小写的模糊包含匹配，并保留命中节点的完整祖先链。搜索只改变可见节点，不改变勾选集合；搜索期间父级批量选择仍以原始完整树的全部后代为准。
- 搜索无结果时保留关键词并提供清空入口；清空后恢复搜索前的展开、滚动和选择状态。右侧详情展示 API Path，以解释按接口路径命中的结果。
- 保存参数为角色 ID、角色版本和去重、稳定排序后的完整 `direct_resource_ids`。
- 当已授权 Menu/Page 没有任何已授权下级 Function 时，提示页面内接口操作仍可能返回 403。

### 数据权限

- 域目录：系统、域编码/名称、支持范围、SELF 解释、状态、关联资源、配置有效性和异常资源。
- 角色域：是否配置、范围、目标 Tenant、当前有效性、原因、版本。
- CUSTOM 需要至少一个同集团有效 Tenant；非 CUSTOM 不保留目标 Tenant。

### 角色分配

- 直接分配：成员编码/姓名、角色编码/名称/类型、管理员身份、集团控制、已分配、当前有效性、可维护、原因、成员版本。
- 页面只有“按角色查看”一种模式；查询支持 Tenant、角色、关键字、状态和服务端分页，请求只提交 `role_id`，不得同时提交 `tenant_user_id`。
- “添加成员”从当前 Tenant 有效成员中选择一个未直接分配该角色的成员，并使用其 `member_version` 调用 `MemberRole/Assign`；“移除成员”使用同一版本调用 `MemberRole/Revoke`。页面不提供无实际结果的详情操作。
- 当前接口没有独立的角色成员关系启停操作；不得以 `Membership/ChangeMemberStatus` 代替。若后续需要启停，后端必须提供关系级 `status + version` 接口后再接入。
- Tenant 管理员身份继续由独立受控能力维护，不在此角色成员页混合操作。

## 状态与验收

所有页面必须区分 Loading、Ready、Empty/NoResults、RetryableError、Unauthorized/ReadOnly、Conflict；权限变更后下一次加载或受保护操作使用最新结果。权限树保存失败保留未保存选择；高风险确认在服务端成功前保持打开。无权限、单条越权和配置异常反馈不得泄露目标记录、其他 Tenant 或内部权限计算细节。

# 2026-09-18 最新裁定：角色编码由系统生成

- 新建自定义角色不再要求用户填写角色编码，CreateRole 不提交 `role_code`。
- 角色编码由服务端创建成功后生成并保持不可变；编辑抽屉仅只读展示，UpdateRole 不提交 `role_code`。
- 本裁定覆盖本文后续章节中关于手工填写或编辑角色编码的旧描述。

# 2026-09-20 最新裁定：功能权限改为精确授权

- 后端只认 `iam_role_resource` 中明确保存的资源；父资源不再隐式授予任何后代。
- 用户与成员只读树通过 `source_roles` 解释明确授权来源，不再展示“父级继承”。
- 角色树的父节点复选框是前端显式批量选择当前子孙的快捷操作；子项仍可独立取消，最终提交每个实际勾选 ID。
- 新增 Function 不会自动进入既有普通角色权限集合；上线前的数据展开迁移、SA 补齐与发布顺序由后端方案负责。
